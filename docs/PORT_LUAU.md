# Luau scripts

The PC port replaces the retail script virtual machine (`CRunScript`, `ps2/src/runscript.cpp`) with Luau. Every compiled script on the disc, whether it carries the `SB2` or the `STB` signature, is a program for that one machine. Scripts differ only in the external-function table registered with the interpreter, so this document names four kinds plus event argument scripts:

| Kind | Scripts | Registration |
|---|---|---|
| `action` | `dungeon/act_script`, `mainchr` | `SetActionScript`, `ps2/src/actscript.cpp` |
| `effect` | `dungeon/eff_script`, `dungeon/articles`, `dungeon/sphida`, `event/tbox/*.pack` | `SetEffectScript`, `ps2/src/effscript.cpp` |
| `monster` | `dungeon/monster` | `SetMonsterScript`, `ps2/src/runscript_opcodes.cpp` |
| `event` | `map`, `dungeon/sys_script`, `event` | `SetEventFunc`, `ps2/src/event_func.cpp` |
| `event_arg` | `*_arg*.stb` | `CEventScriptArg::BuildArgData`, `ps2/src/event_func.cpp` |

The scripts' Luau sources live in `port/src/luau/`, mirroring the original paths. They use Luau type annotations with the port's builtin integer and float aliases (`s8`, `u8`, `s16`, `u16`, `s32`, `u32`, `f32`), and the `PRINT` instruction becomes Luau's `print`.

## Tools

`tools/luau` holds the Python tooling the translation is built from:

- `stb/program.py` decodes a script into its header, program table, functions and instructions. Function discovery matches the publisher and the runtime validator: the main function, the program entries and everything they call, plus compiled helpers that nothing calls.
- `stb/cfg.py` builds each function's control-flow graph with dominators, natural loops and a reducibility test.
- `stb/analysis.py` interprets the operand stack abstractly over the whole program. Integer constants are folded with the machine's 32-bit, truncating semantics, which recovers command numbers that the compiler emits as sums such as `60 + 15`. Variable types are inferred from the float address modes, the values stored into each slot, and the arguments callers pass.
- `stb/sources.py` reads each kind's command enum, registration table and handlers from the decompiled sources. For a handler that reads its arguments in order, the order of its `GetStackInt`, `GetStackFloat`, `GetStackString`, `GetStackVector` and `SetStack` calls gives each argument position a direction, a type and a name.
- `stb/catalog.py` builds the command catalog, and `stb/report.py` renders the corpus report.
- `stb/assembler.py` assembles small programs for test fixtures.

`tools/luau/survey.py` scans the published scripts and writes `tools/luau/commands.json` and `tools/luau/REPORT.md`. It reads `data.zip` through 7-Zip, because the archive's entries are Zstandard-compressed. The data source is `--data` (a data root, a `data.zip`, or a directory of extracted scripts), else `DC2_DATA`, else `port/run`, else the per-user data directory. With `--check`, it writes nothing and exits 1 when either checked-in file is out of date. It exits 77 when no game data is available. Both outputs must be regenerated whenever the handler sources, the curation file or the published data change.

CTest runs the unit tests as `Luau.Tools` and the up-to-date check as `Luau.Survey`, which is skipped without game data.

### Transpiler

`tools/luau/stb2luau` turns the published scripts into the Luau modules under `port/src/luau`. `python tools/luau/stb2luau/transpile.py [--data D] [--kind K] [--only PATH] [--check] [--harness] [--seeds N]` runs it; the data source is found as `survey.py` finds it, and `--kind` defaults to `action`. The stages:

- `timing.py` normalizes each script to NTSC timing before anything else, with the eight `script_timing` recipes and the 17 anchors of `port/src/script_timing.cpp`, rewriting the same instructions to the same markers. The expected counts per script live in `stb2luau/timing_inventory.json`, which a test keeps equal to `port/src/script_timing_inventory.inc` until the C++ is retired. A script whose counts differ from its inventory row, or that is absent from the inventory but matches a recipe, is refused. The corpus check (`DC2_LUAU_CORPUS=1`) confirms every published script matches its row.
- `lift.py` interprets each function's operand stack symbolically into expression trees (`ir.py`). Constant integer and float arithmetic is folded as the PS2 computes it. `JMP_FALSE`/`JMP_TRUE` with a pushed result become `and`/`or`. Values still on the stack are spilled into temporaries before a statement that writes what they read or calls a script function.
  - **References.** A parameter that a function indexes with `POINTER_INDEX` or `POINTER_INDEX_FLOAT` is a reference. Every such index in the corpus is the constant 0 (`*p`), and every caller passes the address of one of its own locals or of a constant element of a local array. So the parameter is the referenced value: the callee reads and writes it as a variable, and its caller copies the variable in and back. A call whose result is used runs as its own statement first, after spilling the stack values that read what it writes. The lifter refuses what this cannot express: a pointer index other than 0 (the callee would reach the caller's neighbouring slots), a pointer used as a value, a value passed for a reference, a global passed by reference, two references that may name the same variable, and a variable that is not a float passed where the callee loads `*p` as one (retail's float load would read an integer's bits as a float, where the copied-in value stays an integer).
  - **Arrays.** A `LOCAL_INDEX` whose index is computed at run time makes its array a table: the slots from the base up to the next slot the function names, or the frame's end. Constant indices into those slots become elements too. An interval analysis over the lifted blocks (constants, sums, branches on comparisons, widening to the compared constants) checks that every computed index stays inside its array. When it cannot, the whole frame becomes one table, `frame`, so an index past its array reaches the neighbouring variables as on the PS2, and `vm.index` raises an error for an index outside the frame, which on the PS2 would reach the operand stack or the caller's frame. The translation does not model those slots, so the harness reports such runs as unsupported (below).
  - **Wraparound.** An interval analysis over the lifted blocks bounds every integer: constants, sums, differences, products and negations, branches on comparisons, and widening at loop heads. An unknown integer is any 32-bit value. A value typed `any`, which may hold an integer or a float, is bounded by the range it has when it holds an integer, and only a comparison with a value that is surely an integer narrows it. Globals are tracked within a function, but are unknown throughout any statement or branch condition that calls a script function, since the call may run before their other operands are read, and after a wait. Each integer sum, difference, product or negation it cannot keep inside 32 bits is marked to wrap, as on the PS2: `vm.i32` for an integer, `vm.wrap` for a value typed `any` (a float operand makes the result a float, which never wraps). A guarded counter (`i = i + 1` under `i < n`, `g = g - 1` under `g > 0`) stays plain; an unguarded global counter does not (`global1 = vm.i32(global1 + 1)` in `mainchr/c01` and `robo`).
  - A constant index past the frame names an operand-stack slot. Only a native call's output may take that address, and only where the slot is dead once the call returns: the call's own command slot, or a free slot above its arguments. Its value is dropped (`dungeon/eff_script/mg_fball1.stb` writes a vector's third component into its command slot). An output over an operand still on the stack, which retail would overwrite, or over one of the call's own arguments, which the handler may still read, is refused.
- `structure.py` turns each function's blocks into `if`/`elseif`/`else`, `while`, `repeat`, numeric `for`, `break` and `continue`, using the code layout of the retail compiler (every function is reducible). A `while` loop becomes a numeric `for` only when its start and its variable are integers, an exclusive limit is an integer, since the `for` moves that limit by one, and its step cannot overflow, since retail's step would wrap where the `for` stops.
- `emit.py` prints one `--!strict` module per script, following the Runtime contract below. Locals are declared at the top of each function, typed from the analysis. Outputs take the catalog's parameter names where the handler names them. Programs become handlers on the script table, named from `tools/luau/programs.json` and documented with the enum's comment; `tools/luau/test_programs.py` keeps that file equal to the enums in `ps2/include`. A handler whose whole body calls one argument-free helper is assigned the helper directly (`script.on_death = helper_77acd540`). Other functions are `helper_<offset>`. Truth values are Luau booleans, converted with `if c then 1 else 0` where the machine stores them, and integer conditions test `~= 0`. Integer division, remainder and multiplication of two variables use the `vm` helpers, an integer operation marked to wrap is wrapped with `vm.i32`, and bitwise operators use `bit32`. A float division by a variable uses `vm.fdiv`, since retail exits when the divisor's bits are zero. A reference-taking helper returns its value (when any caller uses it) and then each reference (`var4, var5 = helper_23a8(268.8, -322.4, var3, 800.0, var4, var5)`). An array is a table indexed from 1 (`var27[var26 + 1]`). An integer constant passed to a parameter the callee loads as a float is passed as the float its bits spell, as is an integer constant stored into a variable the script loads as a float. A nonzero integer constant stored into a variable, or passed to a parameter, that the script loads both as an integer and as a float is refused: retail reads the constant as itself until the first float load and as its bits after it, which one spelling cannot express. A callee's loads of `*p` count as loads of its caller's variable, and a global's loads count across the whole script. A computed value that may be an integer is refused in both places, since retail's float load would read its bits, and so is a float variable passed by reference to a parameter that is not a float, where the callee may store an integer. A repeated test in an `if` chain stays a nested `if`, so the dead branch is kept without a duplicate `elseif`. A variable that only a dropped return value reads is not declared. Retail quirks are kept and marked with `-- retail:` comments.
- Helpers that touch no globals and occur in at least two scripts of a kind become `lib/<kind>/helper_<hash>.luau`, named by a hash of their body and callees.
- `api.py` generates `port/src/luau/api/*.d.luau` from the catalog (`python tools/luau/stb2luau/api.py [--check]`).
- The output is formatted with StyLua and checked with `luau-check` (below). `manifest.json` maps each script to its module and the SHA-256 of its normalized bytes, and lists the shared helpers and their users.

The tools are pinned in `tools/luau/toolchain.json` (Luau 0.740 and StyLua 2.5.2 release binaries, with SHA-256), and `stb2luau/toolchain.py` fetches them into `port/build/luau-tools`. `luau-analyze` 0.740 cannot load declaration files, so `tools/luau/harness` (its own CMake project, the same Luau 0.740 tarball) builds `luau-check`, a strict checker that loads `api/types.d.luau` and then the other `api/*.d.luau` before checking, and treats lint warnings as errors, and `luau-harness`, a host that runs a driver script with `require` and an uncached `loadmodule`. Build them with `cmake -S tools/luau/harness -B port/build/luau-harness -G Ninja` and the repo's llvm-mingw.

`--harness` is the differential test. `stb2luau/refvm.py` is a line-for-line Python port of `CRunScript::exe`, including skip mode, and serves as the retail oracle. Like retail it never checks a local index: an index below the frame reaches the caller's frame, and a load or store past the frame reaches the operand stack. It raises an error only where retail exits, or would leave the stack array or read a pointer's bits as a number. `stb2luau/harness.py` runs every program of a script on it: one scenario per program, each program twice on one instance, main, and main followed by every program, per seed. Each kind gets the stack and call depth its `Set*Script` gives it (effects have 0x40 slots and 2 calls). A mock native API answers each call with seeded outputs: unwritten outputs, a zero bias and the script's own constants. Its `STATE` table makes a stored value read back (`ProgSet`/`ProgGet`, monster `VPush`/`VPop`, `VPush2`/`VPop2` and `SetBitFlag`/`GetBitFlag`, effect `SetValue`/`GetValue`, keyed by their index), and its `RANDOM` table keeps the random commands inside their range. An output takes the type the handler writes: the catalogued type, or for a tagged output the type of the variant the call site uses (the tag the analysis gives its destination), and a float output is a float32. An output that copies bits (`copies`, such as `VPop` and `GetValue`) is recorded and returned as raw bits, whatever the variable is read as. For a tagged parameter the harness also checks that the variant the module calls hands the handler the tag retail's call does, so calling `GetMonsterLifeInt` where retail's variable holds a float fails. The harness records the calls, waits, prints, results and final globals, then replays the trace against the Luau module under `luau-harness`, checking every call, its inputs and arity, and returning the recorded outputs. For each call of a reference-taking helper in the script's own functions, the module is emitted with a probe (`__ref`) that reports the referenced values after they are copied back, and the trace holds the values the reference machine's variables have when the callee returns. Variables loaded as floats are compared as the script reads them. Every number compares exactly, NaN matching only NaN and a float zero only the zero of the same sign (a handler can copy its bits into an integer, where -0.0 reads as -2147483648): both machines compute floats in float32, and the host's `cmath.sinf` and `cmath.cosf` are the C library's, which the reference machine also calls (a test checks they give the same bits), so a sine computed in double precision and rounded fails. A native call's inputs compare as the slots the handler reads. On the Luau side the slot is the one the runtime's `MarshalValue` makes: for a parameter of an integer type (and every input of `Ext`, which it marshals as an unknown type) a number that fits an integer becomes an INT, which drops a zero's sign, and any other number a FLOAT; for a float type always a FLOAT. On the reference side it is the slot retail pushed, with its tag. The two are then read as the handler reads the parameter: through `GetStackFloat` or `GetStackInt`, which convert the other tag, for an untagged float or integer parameter (so the float32's bits, a zero's sign included, or the integer compare); as tag and payload for a tagged parameter, one of unknown type or a string (`VPush(0, 1.00000001)` for retail's `1` fails, because the runtime passes FLOAT 1.0 where retail passed INT 1); as float bits through the reference for an in-out parameter. The inputs of an `Ext` call of a command the kind does not register, or of an arity the handler refuses, are read by no handler, so only their numbers compare.

A scenario either passes, fails, or is compared only up to a cut:

- **Prefix only.** A reference run that exceeds its step budget (500,000 instructions) is compared up to its last event, and nothing after that: what the module does from the cut on (another event, an early return, an error) is not checked, and neither are the final globals. Such a scenario is never counted as a pass.
- **Unsupported.** A run that loads or stores outside the running function's frame is compared up to that access, where the module must raise `vm.index`'s out-of-frame error. Retail goes on with the operand stack or the caller's frame, so from there on the translation diverges from retail.

At an unsupported cut, a module that ends, returns or raises any other error fails.

Neither kind fails the run, but both are counted, and each unsupported access is listed with its offset. The harness reports two instruction coverages: of the reference runs, and of what was compared, which counts the instructions each matching scenario ran before its last compared event.

The harness is not a full equivalence check with retail:

- **Numbers.** It runs refvm in float32, as the modules compute, with the C library's `sinf` and `cosf` through `ctypes` (see Numbers).
- **Handler types.** A mock output is written as its handler writes it, without retagging the variable: its catalogued type, or for a tagged output the tag the handler branches on (its first tagged input's, else its destination's), and for the bit-copying VPop, VPop2 and GetValue the type the script reads the variable as. refvm's loads then reinterpret the bits as the machine does, so the module's reinterpretations are checked. An in-out output takes its catalogued type and is always written, and its input is recorded as the float bits the handler reads. For a tagged command the trace records the tag of its first tagged input, and the module's Int or Float variant must match it.
- **Local state.** Locals, including array tables, are compared only through what they make observable: calls, prints, results, probed references and final globals. Reference-taking calls inside shared library helpers carry no probes.

`stb2luau/mutate.py` checks the harness itself. For a sample of shipped scripts it changes each native call argument in turn (the neighbouring float32, a float zero of the other sign, an integer plus a fraction that keeps its float32 but makes a FLOAT slot, the number plus one, and the other Int or Float variant of a tagged call), keeps the changes that the handler would see and that a compared scenario reaches, and requires the harness to fail every one. CTest runs it as `Luau.Mutate`, skipped without game data or the harness tools.

CTest runs `transpile.py --check --harness` as `Luau.Transpile`. It generates the outputs in a scratch directory and fails when any differs from the checked-in output. It checks them with `luau-check` and runs the harness against them. The test is skipped without game data or the harness tools.

## Command catalog

`tools/luau/commands.json` is the single description of the native API that both the transpiler and the generated C++ bindings consume. Each kind records its enum, header, registration table and table size, and lists one entry per registered command:

| Field | Meaning |
|---|---|
| `no`, `enum`, `handler` | Command number, enum name and retail handler. |
| `luau` | API name the Luau scripts call, as `<kind namespace>.<luau>`. |
| `description` | The handler's documentation comment. |
| `source` | Handler definition, as `file:line`. |
| `arity_checks` | The handler's checks of its argument count, such as `!= 3`, or the `case` labels of an arity switch. |
| `uses` | Call sites and files in the corpus. |
| `signatures` | One per argument count: `argc`, `sites`, `files` and `params`, plus `handler_rejects` when the handler's checks refuse that count (the machine then prints "illegal function call"), and `review` notes. |

An output's type is the type of the value its handler writes, which is the `SetStack` overload clang resolves in the handler; a handler argument that is read as a value, not written, is an input.

A parameter has a `name`, a direction `dir` (`in`, `out`, or `inout`; an output is passed by reference and written by the handler, and an in-out reference is also read by it, as the vector commands read the variables they update), a `tagged` flag when the handler reads the slot's integer or float tag (effect `GetRand`, `GetValue`, `SetValue`, `EsSetValue`; monster `VPush`, `VPop`, `VPush2`, `VPop2`, `SetMonsterLife`, `GetMonsterLife`, `EsmSetValue`; action `EsmSetValue`), and a `type` from the catalog's `types` list, or `unknown`. `observed` counts how call sites supply the position, as a direction and a script-side type. `constants` lists the most common constant arguments, as raw material for enums. `name_source` is `handler` when the name came from the handler's accessor order and `curated` when it came from the curation file. Every other name is positional (`arg1`, `out2`).

Hand curation lives in `tools/luau/curation.json`, keyed by kind and then handler name. An entry may set `luau`, `description` and `notes`, and give `signatures` keyed by argument count, each holding `params` overrides by position (`name`, `type`, `dir`, `tagged`, and `copies` for a tagged output whose handler copies the same bits whichever tag it finds: VPop, VPop2, GetValue). `"reviewed": true` clears that signature's review notes. The survey applies curation last, so regeneration never loses it.

## Corpus findings

`tools/luau/REPORT.md` holds the counts. The findings that shape the translation:

- All 1,399 scripts decode. No function has an inconsistent operand stack, irreducible control flow or recursion, so every function can be structured into Luau `if`, `while` and `repeat` statements.
- Integer division, integer remainder and 32-bit wraparound need explicit helpers, because Luau's `//` and `%` floor and its numbers are doubles. The report counts the sites of each construct.
- Every CP932 string round-trips through UTF-8, so the Luau sources can hold dialogue and motion names as UTF-8 text.
- Function bodies are heavily shared: event scripts embed a common library, and one body occurs in every file. This makes shared library modules worthwhile.
- A few scripts call command numbers that their kind does not register, or pass argument counts that the handler refuses. In both cases the retail machine prints a diagnostic and continues. The report lists these scripts. For most of them, the majority of calls are unregistered or rejected; such scripts may have been built against an earlier command table. The translation preserves these calls as calls that do nothing.
  - In the action kind these are `dungeon/act_script/c01win.stb` and `f204a.stb`. They call unregistered commands 6, 7, 13, 14, 44 and 80, and pass arities the handlers refuse (`SePlay` with 3 arguments, `GetShotType` with 6, `CheckPause` with 1, `SeLoopPlay` with 0). They also pass a reference where `ProgSet` reads a value (retail then sets the program number to the pointer's bits), and a value where `CheckEquip` writes an output. Both scripts are on `tools/luau/fallback.json` and run on the interpreter, because the pointer passed as a value cannot be reproduced in Luau. Even `dungeon/act_script/c01.stb` calls `SetTrgAngle` with 0 or 1 arguments, which the handler refuses.

## Runtime contract

Draft. The transpiler (M1) and the runtime (M2) must both follow it; change it here first.

- **Modules and instances.** Each script becomes one module, `port/src/luau/<original path without .stb>.luau`, published loose to `<game root>/scripts/`. A module is a chunk executed once per `CRunScript` instance. Its module-level locals are that instance's SB2 globals, which persist across `run()` calls as retail globals do.
- **The script table.** The chunk builds and returns a table of handlers: `local script = {}`, `function script.setup() ... end`, `function script.init() ... end`, ..., `return script`.
  - `setup` is the script's top-level entry (retail's main function), run by `run(-1)`.
  - A program the engine runs by number is a field named after it. `tools/luau/programs.json` gives each kind's names: `kinds.<kind>.programs[]` with `no`, `enum`, `name` and `description`, taken from `ACTION_PROG`, `MONSTER_PROG` and `EFFECT_SCRIPT_PROG`, with effect programs 100 and 200, which `EFFECT_SCRIPT_PROG` leaves unnamed, from the port enum `EffectScriptProgram` (`port/src/effscript_port.hpp`, under the kind's `port` key). For example, action 100 is `init`, 200 is `loop` and 1400 is `on_death`.
  - A number without a name for its kind is the numeric key `script[n]`.
  - A named program is never also written under its number, and `setup` is never a program name. `*_RUNNING` (-1) has no name.
  - A handler may be any function value, for example `script.on_death = helper`.
  - Only the table's own fields count, so a metatable changes nothing.
  - Presence matters, because the engine asks `check_program` and falls back to its own behaviour when a program is missing. A script defines exactly the programs retail defined. An empty retail program stays as an empty handler, marked "Defined empty, so the engine runs this instead of its default."
- **Shared libraries.** Deduplicated helper bodies that are stateless and do not touch globals live in `port/src/luau/lib/<kind>/` and are loaded with `require("@lib/<kind>/<name>")`. `port/src/luau/.luaurc` defines the `lib` alias so `luau-analyze` resolves the same paths as the runtime.
- **Execution.** `run(no)` maps the number to its handler for the instance's kind (`setup` for a negative number, the `programs.json` name, else `script[no]`), starts it in a new coroutine and resumes it once. `resume()` resumes it. `vm.wait()` yields. The coroutine's end sets `end`. `check_program(no)` reports whether that handler is an own field of the script table. An interrupt budget stops loops that never wait. Errors are logged with the original path, the handler name and number, and a traceback, and the program ends.
- **Native API.** Commands are called as `<kind namespace>.<CatalogLuauName>(in args...)`, with the namespace and name taken from `tools/luau/commands.json`. Pure outputs come back as multiple results, in parameter order. In-out references (handlers that read through the pointer) are passed in and also returned: `x, y, z = monster.SubVector(x, y, z, dx, dy, dz)`. An integer variable passed in-out passes `vm.bits_float(x)` and reads back `vm.float_bits(out)`, since the handler reads and writes float bits; a reference past the frame passes 0.
  - A command with `tagged` parameters also has `<Name>Int` and `<Name>Float` (and `_<argc>` forms) over its tagged signatures, which give every tagged parameter that type: an input is marshalled as that type (an Int variant still passes a number that does not fit an integer as a FLOAT), and outputs are seeded with it and read back as it. The transpiler picks the variant from the tag analysis (`stb2luau/tags.py`), which follows each slot's tag through loads, stores, float loads that retag in place (also through a reference a helper loads as a float), and native writes that keep the old tag. A tagged input gets the variant of its tag; a tagged output gets the variant of the tag its destination slot holds at the call, and its value is converted with `vm.bits_float`/`vm.float_bits` where the variable is read as the other type: `effect.GetRandInt(10)`, `monster.VPopFloat(3)`. A script whose site has more than one possible tag, or passes a reference where a value is read, is refused and stays on the interpreter through `tools/luau/fallback.json`. A reference passed as the value an output-less tagged handler stores makes the handler store nothing, so that call becomes a `-- retail:` comment.
  - Every catalogued arity is also available as `<ns>.<Name>_<argc>`. The unsuffixed name picks the arity from the number of inputs. When two catalogued arities take the same number of inputs (for example `action.InitScript` at 0 and 1, or `monster.GetPos` at 1 and 3), the transpiler must use the suffixed name. The unsuffixed name then takes the arity with the most outputs and logs once.
  - `<ns>.Ext(no, args...)` calls command `no` with arguments marshalled by their Luau type: an integral number becomes INT, any other number FLOAT, a string STR, and a boolean 0 or 1. It returns nothing. Use it for command numbers the kind does not register and for arities the catalogue does not list. The retail dispatcher then prints its "not found ext" or "illegal function call" diagnostic, as in retail.
  - An arity the handler rejects (`handler_rejects`) still calls the handler, which refuses it and logs as in retail. The transpiler emits such calls as `<ns>.Ext(no, ...)`, so the arguments reach the handler with the same bits retail passed. A call whose argument types conflict with the catalogue (a number where the handler reads a string, or the reverse) is refused, and its script stays on the interpreter.
  - An output the handler does not write comes back as `nil`; retail would leave the script's variable unchanged, so the transpiler assigns `x = r or x` where the old value is observable. The declarations type outputs as `number?` or `string?`.
  - Strings are UTF-8 in Luau and CP932 for the handlers. The converted strings stay alive for the life of the process, because handlers may keep the pointer.
- **Numbers.** Luau numbers are used directly. `vm.idiv`, `vm.imod`, `vm.i32`, `vm.ftoi` and `vm.f32` appear only where C truncation, 32-bit wraparound or float32 rounding is observable; an integer operation wraps where the transpiler cannot prove it stays inside 32 bits. `vm.i32` reduces a double, so a product of two integers beyond 2^53 loses its low bits before it wraps. `vm.wrap` wraps an integral value outside 32 bits and leaves other numbers alone, so an operation typed `any` whose result is an integral float outside 32 bits wraps where retail keeps the float. Floats are float32 as on the PS2: every float add, subtract, multiply and divide is rounded with `vm.f32`, `SIN` and `COS` call `vm.sin` and `vm.cos`, which call the C library's `sinf` and `cosf` that the interpreter calls (the host registers them as `cmath.sinf` and `cmath.cosf`; rounding a double-precision sine differs in the last bit), and a float constant is written as the shortest decimal that rounds to its float32 (`0.68`, not `0.680000007`), inside `vm.f32` when that decimal reads as another double (`vm.f32(3.1415927)`). A native call rounds its float arguments itself, so a constant or the last operation of an argument stays bare. In double precision, `arg0 / 180.0 * 3.1415927` gave SetNextRot a speed one ulp off and the first floor's frog turned differently within one frame.
- **Types.** Annotations use the builtin aliases `s8 u8 s16 u16 s32 u32 f32`, declared in `port/src/luau/api/*.d.luau`.
- **Printing.** The `PRINT` instruction becomes `print`, with retail's formatting: the arguments are concatenated with no separator and no newline, a string prints as it is, an integral number in the int32 range prints as `%d` and any other number as `%f`, and other values print nothing. Luau numbers carry no int/float tag, so a float holding an integral value prints as an integer; a site that must show the float uses `string.format("%f", x)`.
- **The `vm` library.** `port/src/luau/lib/vm.luau`, loaded with `local vm = require("@lib/vm")`, provides `wait`, `i32`, `wrap`, `ftoi`, `idiv`, `imod`, `fdiv`, `index`, `f32` (through a vector component, a native float32 conversion), `sin`, `cos`, `bits_float`, `float_bits`, `section` and `skip_end`. `idiv`, `imod` and `fdiv` raise an error on a zero divisor (for `fdiv`, integer 0 or +0.0), where retail exits.
- **Native outputs.** A handler writes an output's bits through the reference without retagging the variable, and the machine's loads read them by their mode and the slot's tag: a float load reads the bits as a float, an integer load as the slot's tag says. `stb2luau/tags.py` follows the tags every slot may hold through each function (stores, float loads, zeroed locals, parameters, references through helper calls, globals) and, for every native call, how each read that a written value reaches interprets it. Where the handler writes the other type than the variable holds, the module reinterprets the output: `x = vm.bits_float(monster.GetRnd(360.0)) or x` for a variable the script loads as a float. A tagged handler's variant follows the tag it branches on: its input's for GetRand, its destination's for GetMonsterLife. A value read both as an integer and a float, or a branch tag that may be either, is refused.
- **Fallback.** `tools/luau/fallback.json` lists the scripts the translation refuses, with the reason; they have no module, so the game runs them on the interpreter. Besides the tag cases, a script is refused when a native call reads a reference's slot as a value (the PC interpreter reads the low bits of the variable's address, which vary from run to run), or a string as a number or the reverse. `transpile.py` fails when a listed script transpiles or an unlisted one is refused, and the manifest lists the listed scripts under `interpreter`.
- **Arrays.** A local array that the script indexes with a computed index is a Luau table holding its slots from index 1. Where an index may leave its array, the function's frame is one table, `frame`, slot `n` at `frame[n + 1]`, and `vm.index(i, n)` maps a computed slot to its place, raising an error outside the frame.
- **References.** A script function's reference parameter (`*p`) is a plain parameter. The function returns its own value, when a caller uses it, followed by the final value of each reference, and the caller assigns them back: `x, y = helper(a, x, y)`.
- **Skip mode** (event scripts only). Code between skip ends becomes `vm.section(function() ... end)`; `vm.skip_end()` ends a section.
- **Argument scripts** become data tables.
- **Loading.** No `.stb` bytes are published. The port's file layer maps each `.stb` request (fixed paths, pack members, language fallbacks and names that scripts build) to its Luau module, for example through a synthetic in-memory handle that the overridden `CRunScript::load` recognises.

## Runtime

`port/src/luau_runtime.{hpp,cpp}` runs the modules, and `port/src/runscript.cpp` routes `CRunScript` to it.

- **Facade.** `CRunScript::load`, `run`, `resume`, `check_program`, `skip` and `DeleteProgram` are overridden. When the loaded program is a Luau handle, they go to the runtime. Otherwise they call the retail bodies, which `scripts/port/unit_copy.py` keeps as `PortRetailLoad`, `PortRetailRun`, `PortRetailResume`, `PortRetailSkip` and `PortRetailDeleteProgram` (declared on the class by `scripts/port/header_fixups.py`). So every kind without modules, and every `.stb` without one, still runs on the interpreter. `ext`, `rsGetStackInt` and `rsSetStack` are unchanged. `load` still assigns the stack and call slots it is given, so the engine's checks see a loaded script.
- **State.** There is one `lua_State`, sandboxed with `luaL_sandbox`, holding the standard libraries, `print`, `require` and one read-only global table per native namespace. Native code generation is enabled when `luau_codegen_supported()` reports it; it does on Windows x64 with llvm-mingw. Each instance is a registry entry keyed by its `CRunScript *`. It holds a thread made with `luaL_sandboxthread`, whose globals table is the instance's, and the program table the module returned. A module file is compiled once (`optimizationLevel` 1, `debugLevel` 1). Each instance runs a clone of the chunk with the thread's globals as its environment, so module locals are per instance. An instance is used only while `prog` still points at the handle it was loaded from, and `load` and `DeleteProgram` (which the constructor calls) forget the old one.
- **Execution.** `run(no)` finds the handler: `setup` for a negative number, the name `programs.json` gives the number for the instance's kind (from its data path: `mainchr/` and `dungeon/act_script/` are `action`; `dungeon/eff_script/`, `dungeon/articles/`, `dungeon/sphida/` and the pack members under `event/tbox/` are `effect`; `dungeon/monster/` is `monster`), else `script[no]`, all read with raw access. It makes a new coroutine for the handler, resumes it, and returns 1 if it yielded or 0 if it finished, setting `end` and, from a numeric return, `result`. A missing handler returns -1 and logs once. `check_program` makes the same lookup. `resume` and `skip` resume a yielded coroutine. An interrupt callback counts safepoints from each entry and raises an error after 10,000,000 (`SetInterruptBudget`). An error logs `luau: <path>.stb: <handler> (<no>): <message>` with the coroutine's traceback under the `Script` category, and ends the program.
- **Program names.** The build also generates each kind's number-to-name table into `luau_bindings.cpp`, from `tools/luau/programs.json` (`bindings.py --programs`).
- **Native calls.** `tools/luau/bindings.py` turns `tools/luau/commands.json` into constexpr signature tables (`port/src/luau_bindings.hpp`). The build generates them into `<build>/generated/luau/luau_bindings.cpp` for the kinds `CT_LUAU_KINDS` lists in `port/cmake/luau.cmake`, currently `action`, `effect` and `monster`. The output is deterministic and rewritten only when it changes. Each `(command, argc)` becomes a C closure.
  - A call builds the slots on the stack: the command number, then INT, FLOAT or STR inputs as the catalogue types them, and PTR slots for outputs, seeded with an unwritten marker. It calls `CRunScript::ext` on the running instance, so `script_guards` and the retail handler run as they do for the interpreter.
  - Outputs return as floats for `f32` and integers otherwise. An `unknown` output is read as a float when its bits are a plausible float.
  - Strings are converted to CP932 with `legacy_encoding::GameText` and interned for the life of the process.
- **Loading.** `ResolveFile` (`port/src/dataread.cpp`) asks `ModuleForScript` about every `.stb` key. For keys of the action, effect and monster kinds, when `<scripts>/<key without .stb>.luau` exists, it returns a handle instead of the file: `LUAU`, the module key's length and the key, padded to 16 bytes. Every loader then copies the handle as it copied the script (`LoadFile`, `LoadFile2` and `LoadFileBG`, so `CActionChara::LoadActionFile` and the `menuchr.cpp` loads), and the overridden `load` recognises it. The effect loaders `BuildPack` and `LoadBaseEffSpt` read scripts through the port's `EffectScript`, and pack members through the asset directory behind `GetPackFile`; both ask `ModuleForScript` too. `ModuleForScript` never returns a module for a script on `tools/luau/fallback.json` (the build passes the list to `bindings.py --fallback`), so an old copy of its module cannot bring it back to Luau.
  - `<scripts>` is `<game root>/scripts` when it exists, else `scripts/` beside the executable. The build copies `port/src/luau/**/*.luau` there, without the `.d.luau` declarations, and `cmake --install` installs them to `<bindir>/scripts`. Both remove the modules they copied earlier whose sources are gone (`port/cmake/scripts/luau_prune.cmake`, which records what it copied, with its hash, and leaves alone any file it did not copy or that changed since).
  - `require("@lib/<name>")` loads `<scripts>/lib/<name>.luau` once per state.
  - `DC2_SCRIPT_VM=interpreter` turns Luau off and runs every script on the interpreter, which is how replays compare the two.
  - The `.stb` files are still published and still validated for NTSC timing at startup, because event scripts still run on the interpreter. Publication stops after event scripts move to Luau (M4).
- **Tools.** `ct_luau_tools` builds `luau-analyze` and `luau-compile` from the same source. `dc2data export-scripts <data.zip or game root> <directory>` writes every published `.stb` at its archive path, the corpus that `tools/luau/survey.py --data <directory>` and the transpiler read without 7-Zip.
- **Tests.** `port/src/tests/luau_runtime_test.cpp` covers the facade with the modules in `port/src/tests/luau/`: run, wait, resume and end, named handlers by kind, per-instance globals, main's result, missing programs, outputs and unwritten outputs, CP932 strings, float inputs, `Ext`, suffixed and ambiguous arities, errors, the interrupt budget, bad modules, `DeleteProgram`, handles, the action key mapping, `print` and the interpreter fallback.
