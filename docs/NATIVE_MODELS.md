# Native models and characters

Kazarov converts MDS, MDT, MOT, WGT and BBP resources into standard glTF 2.0 and an adjacent, pretty-printed `.game.json` document with `schema_version: 1`. A CHR becomes one glTF containing its models as separate scenes and compatible animation clips. Nested characters become child glTF files under the parent's `.assets` directory. Runtime code opens physical paths directly; no model catalog or alias manifest is published.

The converter follows the documented retail records in mg_dataset.hpp, mg_visual.hpp, gameutil.hpp and visualmotion.hpp. Standard nodes retain frame order, names and parent-child relationships. Static nodes retain matrices; animated nodes use translation, rotation and scale. Coordinates retain game units and axes. Animation times use seconds at 30 game frames per second. Retail scalar-first quaternions become standard glTF scalar-last conjugates, preserving the actual retail rotation matrices. Animated nonuniform scales use a translation/scale parent and rotation child so the standard node hierarchy preserves retail T*S*R order. The parent keeps its original frame node index; meshes, skins, morph weights and descendants move to the rotation child. Authored basis scale remains in the rest pose and resets to one in rotation clips, matching the matrix setter.

MDT corner streams become standard position, normal, UV and colour attributes. Sidecar primitive mappings preserve independent source stream identities for CPU deformation. Normalized normals and clamped colours meet glTF requirements. Sparse `stream_overrides` retain only components standard reconstruction cannot reproduce: fourth components, nonunit normals, unclamped colours and unused source elements. Full geometry streams are not duplicated.

WGT data becomes standard joint attributes, weights, skins and inverse bind matrices. Only nonempty lists introduce bones. Inverse binds use inverse(base_bone) * base_mesh, using BBP matrices when available. CPU shadow deformation can exceed the GPU visual's 32-bone limit. MOT TRS lists become standard LINEAR channels. Vertex motion becomes sparse morph targets and animated weights. Camera, material and visibility operations remain semantic channels where core glTF cannot express them.

Matching stems and explicit profile relationships select candidate animation associations. Referenced frame IDs must fit the model before tracks join its skeleton. An incompatible clip retains separate named standard nodes. Same-stem standalone resources share one glTF without overwriting geometry. The e213a regression covers incompatible skeletons.

All buffers and PNGs are embedded data URIs. Default material pictures use standard PBR textures. Character texture sets retain schema 3 semantics in the sidecar, with every mip and variant embedded and level references written as `#/images/N`. Sidecar `images` rows contain an image index and original physical PNG path for direct datapack replacements.

The three retail memory-card icons become pure standard glTF files under title. Each contains 156 vertices, one shape and a constant base-shape animation key, so no animation channel or gameplay sidecar is required. Positions retain the icon renderer's Y/Z flip; normals are unit vectors, UVs and vertex colours are standard attributes, and RGB555 run-length texture data becomes an embedded 128×128 PNG. Native icon rendering reads glTF rather than PS2 model or PACK records.

## Semantic sidecar

Character documents contain `kind: "character"`, models, profiles, default_profile and resources. Default profile selection follows original CFG member order. Model rows select standard scene and node_offset and preserve native frame-to-mesh identities, draw types, source stream mappings and raw material diffuse/ambient values. Standard geometry, transforms and skin data remain authoritative in glTF. Optional frame.rotation_node identifies an appended standard rotation child for native frame collapse. Animation-only rotation_nodes maps helper node indices to source frame indices; merged null-model variants shift the standard node indices without changing source frame identities. A standalone glTF that also contains an incompatible animation-only skeleton uses animation_node_offsets only for its shifted standard clips; the global rotation_nodes map retains local source frame values.

Profiles hold ordered typed commands. Resource operands use type resource, a kind and integer index into models or the corresponding resource array. Null preserves an absent optional resource. Gameplay values retain their types. Resources include standard animation descriptors and variants, bind matrices, weight lists, cloth commands, texture sets, direct child glTF paths and STB script paths. Standard TRS keys are not duplicated.

STB executable gameplay bytecode remains a separate directly referenced .stb file. Script descriptors identify required texture sets or a child character bundle. CLO data becomes typed commands. Sidecars omit source aliases, opaque source bytes, reserved words, padding and redundant frame matrices. Standalone models and animations use the same native identity concepts without character profiles.

## Publication and validation

Direct proprietary model and CHR files disappear. Ordinary PACKs become physical asset directories with minimal pack.json markers. Only surviving published payloads move into those directories; consumed resources never return from the raw inventory. Embedded scene ranges are scrubbed before directory publication. Duplicate members and embedded offsets receive distinct deterministic physical paths. The distinct standalone a_mu and sukkopu models in etc/gsys.pak use `.model.gltf` names to preserve their sibling character profiles. The identical standalone hake geometry shares its character glTF. Other unresolved character/model collisions fail conversion.

models::verify walks actual glTF/sidecar pairs, validates schemas, embedded PNGs/buffers, accessors and sparse ranges, nodes, materials, skins, inverse binds, animation channels and direct character resources. It rejects retained model and CHR payloads. Tests cover incompatible clips, output collisions, optional standard fields, shadow slots, sparse semantic components, PACK compaction and retained-payload rejection. Ignored tests audit retail PACKs and the extracted disc in isolated outputs.

`tools/kazarov/scripts/audit_blender_gltf.py` imports every published `.gltf` and `.glb` using Blender's actual importer. Run it against `port/run/port_data` with `--blender <executable> --report <report.json> --jobs 6 --batch-size 64`. It resets Blender data between files and recycles each worker after a batch. The pretty JSON summary and adjacent JSONL checkpoint retain per-file outcomes, errors, timings and peak worker memory. A repeated run resumes unchanged files for the same Blender version; `--retry-failed` retries failures and `--no-resume` imports everything again. Timeout or worker termination produces an explicit failed result while unstarted files continue in a fresh worker.

For an audit performed against a private snapshot, rerun the auditor with `--verify-published port/run/port_data --verify-only`. It requires a complete passing report, identical file coverage and unchanged audited fingerprints. Hardlinks are checked by physical file identity; copied files require matching SHA-256 hashes. The result is stored as `published_identity` in the report.
