# Published audio resources

Audio extraction reads the retail resources once in Rust. Runtime sound loads PCM WAV and versioned semantic JSON, and movies load self-contained MP4 files with embedded audio. `data/` contains neither HD/BD/SQ/MIDI/voice WAV/PSS resources nor the original SOUND archive; converted standalone sound archives are removed; any audio member inside an otherwise retained archive has its payload removed.

The game names each published resource directly. A sound archive such as `snd2/sy_000.snd` becomes `port_data/snd2/sy_000.sound.json`. This document has `schema_version: 1`, `kind: "sound_bundle"`, and these fields:

* `bank`: the root-relative bank JSON URI, or null for a bundle without samples.
* `sequences`: ordered root-relative sequence JSON URIs.
* `effect_sequences`: ordered root-relative effect sequence JSON URIs.
* `config`: the root-relative sound effect mapping JSON URI.
* `volume`: the root-relative default volume JSON URI.

For this example the referenced resources live under `snd2/sy_000.sound/`: `bank.json`, `samples/N.wav`, `sequences/<name>.json`, `effects/<name>.json`, `config.json`, and `volume.json`. Sequence order follows the original archive member order, preserving game indexes. Voices use `sound/<name>.wav`; movies use `movie/<name>.mp4`. All JSON references are actual filesystem paths relative to `port_data/`. There is no global audio catalog or runtime retail-name mapping. Original converted sound archives and voice/movie files are removed from `data/`.

Bank documents have `schema_version: 1`, `kind: "bank"`, and ordered `programs`, `sample_sets`, `samples`, and `vags` arrays. Missing programs have `present: false`. Present programs contain `volume`, `pan`, signed `transpose`, signed `detune`, and `splits`. Each split contains `sample_set`, inclusive `key_low`/`key_high`, `bend_low`/`bend_high` in 128ths of a semitone, `volume`, `pan`, `transpose`, and `detune`. Sample sets contain `vel_curve`, inclusive `vel_low`/`vel_high`, and sample indexes. Samples contain `vag` (a PCM sample-table index), inclusive velocity bounds, `base_note`, `detune`, `pan`, `volume`, `adsr1`, `adsr2`, and `spu_attr`. The original hardware envelope and routing parameters remain synth parameters rather than a binary bank image.

Each non-null PCM sample-table entry contains `wav`, `attr`, `loop_start`, exclusive `loop_end`, and `loops`. Loop boundaries are mono sample-frame indexes. WAV files contain signed 16-bit little-endian PCM with one or two channels and the source sample rate. SPU prediction and loop flags are decoded only by the extractor.

SQ documents have `schema_version: 1`, `kind: "sequence"`, and `songs`. Each song has `division` (ticks per quarter note) and normalized `events`. Events contain `delta` ticks and `kind`: `channel` carries `status` and two `data` values; `meta` carries `meta` and a `payload` byte array; `sysex` carries a `payload`; `end` terminates playback. These arrays describe musical events, not reserialized SQ bytes. Tempo meta events, controller loop markers, running status and Sony's omitted-delta convention are resolved or retained semantically as appropriate. Runtime loop cursors address event indexes.

Effect MIDI documents have `schema_version: 1`, `kind: "effect_sequence"`, `tick_rate`, and `events`. Events carry the retail effect player's signed 16-bit `delta`, `status`, and two `data` values. Playback preserves the effect driver's `division * 225 / 60` tick rate and its discarded meta-event delays. MIDI parsing occurs during extraction.

Sound CFG documents have `schema_version: 1`, `kind: "sound_config"`, `entry_count`, `entries`, and `reverb`. Each entry holds `filename`, signed `program` and `key`, and Boolean `flag`. The `filename` of a sequence entry is its explicit JSON URI, matching the ordered bundle reference; `KeyOn` and empty/unknown effect markers retain their semantic meaning. `entry_count` preserves the retail sound table's allocation count, including non-effect lines. VOL documents use `kind: "sound_volume"`; each entry contains `index` and signed `volume`. Both documents contain typed reverb commands as `{ "type": integer, "depth": integer }`. Source CFG/VOL scripts belonging to sound packs are removed. Other CFG resources use the [general JSON configuration pipeline](PORT_CONFIG_FORMAT.md).

Scene sound routing uses two direct documents. `snd2/rev.json` has `schema_version: 1`, `kind: "scene_reverb"`, and ordered `rows` containing signed integer `id`, `type`, and `depth`. `snd2/map_index.json` uses `kind: "scene_sound_routes"`; its rows contain `id`, `bgm_no`, `se_base`, `se_battle`, `se_env`, `env_bgm`, `env_vol`, eight `se_src` values, two `event_se` values, and `reverb_id`. Negative bank values preserve missing (`-1`) and keep-current (`-2`) behavior. Routes resolve `reverb_id` against the reverb document when loaded, so reverb overrides apply to routing too. Labels and unused binary padding are omitted. The original `snd2/rev.bin` and `snd2/MAP_index.txt` are removed from publication.

Rust converts movie audio from SShd/SSbd private PES data. Planar channel groups become interleaved PCM, and the difference between first audio and video PTS values is applied as leading silence or trimmed frames. FFmpeg copies the original MPEG-2 video into MP4 and encodes the aligned audio as lossless ALAC in the same file. Published MP4 tracks start on a shared zero-based playback clock; the MP4 track timestamps preserve their playback alignment. Temporary mux inputs are deleted, and no separate movie WAV is published. The converter locates FFmpeg through `KAZAROV_FFMPEG`, a sibling executable, an available configured development path, or PATH, in that order.

Standard JSON, WAV and MP4 assets resolve at their declared paths through active datapacks before the base `port_data` fallback; malformed replacements fall through to valid lower-priority files. To replace a bank sample, place a PCM WAV at the bank's referenced relative path in an enabled pack. Bank JSON can also be replaced to change splits, envelopes and loop boundaries. Replace a movie with one MP4 at the same path, including its audio; H.264/AAC overrides are supported alongside extracted MPEG-2/ALAC files. Native game path producers and configuration resource operands name these files directly. No retail bank, ADPCM, SQ, sound CFG/VOL or SShd audio parser is linked into the port.
