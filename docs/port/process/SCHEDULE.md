## 2. Hard rules (verbatim in every brief)

1. Replacement through `PORT_OVERRIDE` only, written from scratch; a `static` function's non-static callers are replaced instead; asm definitions are guarded `#ifndef PORT` and defined untagged in `port/src`, declared by `port/include/stubs/<unit>.hpp`.
2. No PS2 emulation: no GS register interpreter, no VU0/VU1 interpreter, no VIF/GIF packet decoder, no DMA chain walker, no SPU2 model, no IOP, no memory mapping of PS2 address ranges (scratchpad, uncached mirrors, registers). Packet-building code in `ps2/src` is replaced, never decoded.
3. Native Vulkan 1.4 through the shared Kazarov renderer (`tools/kazarov/src/cpp/gfx`), every pipeline precompiled at `RendererInit` with the pipeline cache.
4. VU1 programs are replaced natively from `docs/vu1/<program>.md`; the spec's test vectors become test expectations. Where the spec and the plan disagree, the spec wins.
5. Renderer, audio, game-agnostic platform and SDK replacements live in Kazarov and are extended there for DC2 behind specialisation constants, new files or selectable `sce` families so Chronicle's compiled code does not change. Game glue lives in `port/src`.
6. No hardcoded resolution or frame rate: logical 512x480 for 2D mapped aspect-correct, 3D at window resolution, logic tick at `settings.tick_rate` (default 50) with `mgFrameRate` keeping its meaning, presentation independent of the tick. Rule 14 says how.
7. No PS2 memory quirks: no 32-bit pointer round trips, no `mgMEMORY_BLOCK` with a 4-byte pointer, no scratchpad staging, no uncached writes. No overlays, no IRX: `sceSifLoadModule` and the IOP reboot are no-ops. An address the game keeps in an integer is a `uptr` (rule 12), never an `int`.
8. Game data is `data/` written by `tools/dc2data`, read with `std::filesystem`; saves go to `save/`. Asset conversion is a last resort; movies are PSS demuxed by the port with MPEG-2 video decoded by a minimal LGPL `libavcodec` (plan section 3.9), the only third-party decoder.
9. PCSX2 may be read to understand hardware; nothing is copied from it.
10. The PS2 build stays byte-identical: `./build.sh ps2-pal` then `verify.py -c` after any `ps2/` edit.
11. Comment policy: "Act as a brutal, no-nonsense senior engineer. Do not explain what the syntax does. Assume the reader is an expert who reads fluently. Only add comments to explain why a non-obvious engineering decision, business logic constraint, or optimization workaround was made. If the code is self-explanatory, leave no comments."
12. **`uptr` (revision 2).** `ps2/include/types.h` defines, under `#ifdef PORT`, `typedef __UINTPTR_TYPE__ uptr; typedef __INTPTR_TYPE__ sptr;` and otherwise `typedef unsigned int uptr; typedef int sptr;`. In `ps2/src` and `ps2/include`, every cast of a pointer to `int`, `u_int`, `s32`, `u32` or `long`, every local, global and non-record field that holds an address in such a type, and every integer return type that carries an address becomes `uptr`. `sptr` is used only where the integer form is signed-sensitive to MWCC: compared with `<`, `>`, `<=`, `>=`; shifted right; divided or reduced modulo; converted to float or double; widened into a 64-bit `long`/`u_long`; or stored in a signed field that is so used. For every other operation `unsigned int` and `int` compile to the same MIPS instructions, so both choices keep `./build.sh ps2-pal` byte-identical, and `verify.py -c` proves it after every batch. Parameter types never change (MWCC mangles them): a parameter that carries an address makes its function and its callers an override pair on PC, owned by the unit's stream and listed in `docs/PC.md`. Return types may change (not mangled). A hand-written pointer stride (`<< 2`, `* 4`, a `sizeof(void *)` that means 4) is a separate defect: rewritten to index form in `ps2/src` where `verify.py` shows identical code, else kept as a port override documented as a stride fix. No port override may exist whose body differs from retail only by widening once W2.u has landed. `scripts/port/truncations.py --check` knows the two types, counts narrowing pointer casts in compiled `ps2/` code outside `#ifndef PORT` asm, and fails on any open round trip in linked code.
13. **Records (revision 2).** A struct whose instances are read from a file in place is a record: its layout is the disc's on every host; its pointer-sized fields stay the 32-bit offsets retail wrote (never `uptr`, never a pointer); `PORT_RECORD_ASSERT(sizeof(T) == N)` (a `static_assert` on PC, nothing on the PS2) holds beside the PS2 `STATIC_ASSERT`; and no code writes a pointer into one. A record's offsets are resolved on access (`(u_char *) header + header->x_ofs`, the idiom MDT/MOT/IMG already use) or decoded into a host table by the unit's port file (DATA.HD4, PACK, script stacks). In-image tables of pointers are arrays of pointers with `sizeof(void *)` strides, never `base + i * 4`. `docs/port/records.md` classifies every `STATIC_ASSERT(sizeof)` struct as record or runtime with its reader and approach.
14. **Ticks, display frames, aspect (revision 2).** Game logic reads only logical coordinates: `mgScreenWidth`/`mgScreenHeight` stay 512/480, `mgScreenOffx`/`mgScreenOffy` stay the 2048-centred GS offsets, and nothing in `port/src` outside `platform/` and `mglib.cpp` reads the window's pixel size (grep gate). Culls, clips and screen-bound tests take their extents from `gfx::VisibleLogicalRect(target)`, not from 256/240 half extents; the 2048 guard band stays. Every tick is recorded as a `gfx` display list, rendered once as its canonical image (what `kPreviousFrame`, frame grabs, `mgPickZBuff` and `--screenshot` read), and display frames between ticks replay the newest list with model matrices, bone palettes and the camera interpolated at alpha = elapsed fraction of the tick, as fast as `present_mode` and `max_fps` allow (`max_fps` 0 = unlimited). Not interpolated: 2D without depth (HUD is tick-exact), 3D sprites' own motion, objects or cameras past the teleport thresholds, the first tick of a mode, lists after `CutInterpolation()`. `interpolation = off` presents each canonical image once. Headless: one canonical image per tick; `--display-per-tick N` renders N interpolated frames per tick and changes no screenshot. 3D field of view follows the window aspect (`AspectMode::Fill`, the frame's rows fill the height); 2D stays in the logical frame with the full-frame rule; HUD pieces are anchored with `gfx::UiAnchor`; `aspect = 4:3` letterboxes byte for byte. `mgFrameRate` keeps its meaning (ticks per game frame: 2 = 25 game frames a second on the 50 Hz tick), and display frames are still presented at the display rate.

#### Display-list and aspect contract (binding for every W3 rendering stream)

The W3 rendering streams write their draws once, against this contract, so `present-core` and `present` need not revisit them:

1. **Submission goes through the seam** (`mglib_port.hpp`: `mgPortDraw2D`, `mgPortDrawMesh`, `mgPortDrawMeshImmediate`), never through `gfx::` directly, so the recording of a tick's list is the seam's business. Creating textures, meshes and render targets through `gfx::` is fine (they happen at once).
2. **Every mesh draw carries a `gfx::MeshTransform`** built by `mgPortMeshTransform(model)` (projection, view and model kept apart; `mvp` is their product), and is **tagged** with `gfx::SetInterpKey` (through the seam's scope helper, which `present-core` adds on day one: `mgPortInterpScope(const void *object, float teleport_distance, bool blend_vertices = false)`) keyed by the `mgCFrame *` the visual is drawn under, or by the visual's own record when drawn outside a frame. Teleport distance for frames: 200 world units (as Chronicle's `kDraw3DTeleportDistance`; retune if DC2's units differ, stated in the report). Shadow volumes and anything rebuilt in eye space are tagged `no_interpolation`; the cloth-like cases (vertices that are the same grid points in world space each tick, under an identity model) use `blend_vertices`.
3. **No eye-dependent decisions are baked into a draw.** Back- or front-facing selection is `DrawState::cull`; shadow volumes are recorded wound outward and counted by a back-culled adding draw and a front-culled subtracting draw (Chronicle's rule), so a display render under an interpolated camera is still right.
4. **Skinning.** `prog0` keeps the bone palette in the DC2-only per-draw block (the one it moves out of `MeshConstants`) as model-space bone matrices, not pre-multiplied with the view or the projection, 32 slots, so that `present` (W4) can interpolate it per bone. Until then poses are the tick's.
5. **Culls and clips** (`mgCFrame::GetDrawRect`, `mgGetDrawRect`, the screen-bound test in `mg_frame`, `map.cpp`'s `screen_rect`, `outline.cpp`'s `max_xy`, `mgClipBox*` callers) take their extents from the seam's `mgPortVisibleExtent()` (`present-core`, day one: `gfx::VisibleLogicalRect(mgPortCurrentTarget())` in the game's units), never from `mgScreenWidth`/`mgScreenHeight` halves. The GS guard band (2048) stays.
6. **2D** stays in logical 512x480 space through the seam. A 3D sprite is 2D that tests depth, recorded as the tick's screen corners, which the display render carries to the interpolated camera; its own motion is not interpolated. Full-frame fills, fades, previous-frame feedback and grabs drawn back reach the window's edges by the renderer's full-frame rule, with nothing to do in the stream; HUD pieces are plain textured quads (anchoring is `present`'s, W4).
7. **Frame grabs** (`mgSetPkMoveImage` copies of the frame, the menu's frame grab, water's field copy, DOF's downsamples, photo's readbacks) go through the seam's frame-target entry points (`mgPortRenderTarget` with `frame_target = true` for grabs of the frame), so a grab is as wide as the window and a display frame takes it again from its own image.
8. **Readbacks** of colour (`mgStoreImage`, photo) read the canonical image (the seam answers from the last canonical render); `mgPickZBuff` queries are logical-space rects.
9. **Nothing reads the window size.** `mgScreenWidth`/`mgScreenHeight` are 512/480, logical; the window's pixel size is the mapping's business.

**Decision: DC2 interpolates skinned poses.** Chronicle does not need to: its skinning is CPU (`MotionProc2`) written with `UpdateMeshVertices`, which the display list already blends vertex by vertex, so a character and what hangs from it move together. DC2 skins on the GPU (W1's `mesh_prog0.vert`, 32 bones), so a pose is a bone palette in the draw's constants, and left at the tick's pose a body would step at the logic rate (25 Hz wherever `mgFrameRate` is 2) while its position, the camera and its weapon slide: the most visible judder there is, and the opposite of what the user asked for. So `present` (W4) interpolates a matched draw's palette per bone as it interpolates a model (translation lerped, rotation slerped, scale and shear lerped in the rotation's frame), a bone that moved further than the draw's teleport distance snapping, from the model-space palette `prog0` records (item 4). Cost: skinned draws only (tens per tick) at 32 bones. Chronicle is unaffected: no palette, no path. Headless `--display-per-tick N` must leave screenshots byte-identical with it on.

## 8. Risks

- **WP4.1 is the Phase-4 bottleneck.** Mitigated by `mglib_port.hpp` being published (frozen, committed) within the stream's first day and by the W2.c checkpoint; `vu1-geom` and `textures` code against gfx directly, not mglib.
- **Fibers on Windows.** `--allow-multiple-definition` lets the game's `CreateThread` shadow kernel32's; a fiber switch inside SDL/Vulkan callbacks would corrupt state. `time` must prove no switch happens outside `RotateThreadReadyQueue`/`WaitSema`/`WaitVSync`-class calls, on both OSes, with tests.
- **long64 rewriting** changes every build-tree copy; it must preserve line numbers (port_override diagnostics) and not touch string literals, format strings (`%ld`) or `long double`. `boot` owns the proof; the fallback is per-function overrides.
- **Two streams in `gfx.hpp`** (Wave 3). Regions are named; the integrator merges and rebuilds Chronicle.
- **Chronicle pixel identity** is the only proof a Kazarov change is safe; the baseline screenshot must come from `ce459c1` before anything else is merged (W0 step 4).
- **Image rebuilds** (movies-base Dockerfile) cost ~15 min per checkout; they land once at W2 integration.
- **Shared `data/` through junctions**: any `run.sh` in a worktree or a stale `.kazarov-data` stamp triggers a re-extraction into the shared tree. The no-`run.sh`, no-`rom/` rule in worktrees is the guard; `data/` ownership is the integrator's.
- **Haiku on decision WPs.** Opus must read every diff (`git diff`) before accepting it and reject work that decodes packets, maps addresses or copies from Chronicle/PCSX2; large WPs are cut into tasks of one function family each with the retail lines named.
- **One ctest process per case** makes the Windows and Linux test runs long; `-j4` and the clock cases serial, as configured.
- **SOUND.HD3 unknown**: `audio-base` may end with a documented partial format; `audio-game` then keeps streams silent and `StreamGetState` stopped, as the plan allows.
- **LGPL FFmpeg**: the BtbN tag must be a dated `autobuild-*` release with the `lgpl` variant; pinned SHA-256s; the pytest guards the configure line.
- **CPU oversubscription**: five streams building at `JOBS=8` plus lavapipe tests exceed 32 threads; the cap of four heavy builds and the integrator's gate priority are the rule.
- **Windows `CreateThread`/`u_long`/`mgSetPkTEX0`** open issues depend on `boot`'s long64 decision; `mglib` (W2) inherits them if not closed.
- **`uptr` and MWCC (revision 2).** `unsigned int` vs `int` differs only in the signed-sensitive operations of rule 12; `sptr` covers those, and the ps2-pal gate runs after every batch of units so a drift is caught within one batch. A site where neither type matches (an expression MWCC scheduled around the signedness) stays retail with its override assignment recorded; the gate for the stream is the count of such sites, not zero at any price. Mangled parameter types are the hard line: no parameter changes.
- **`uptr` header changes vs running streams.** Field and return type changes break compiles in W3 worktrees at their rebase; the W2.u message tells them to expect it, and the integrator handles what is left at W3 integration. `ps2/` is closed to everyone but `uptr` while it runs, so there are no textual conflicts.
- **Records mis-classified.** A runtime struct wrongly marked record keeps a 32-bit field that then truncates; a record wrongly marked runtime gets a pointer-sized field and misreads the disc. `records.py` guards the second (the `PORT_RECORD_ASSERT` list compiles against the host `sizeof`); `truncations.py` guards the first (a narrowing cast on it shows up). Both are in the gate.
- **Bone interpolation cost and correctness.** Per-bone decomposition for tens of skinned draws per display frame is cheap; the risk is a palette recorded pre-multiplied (then slerp is meaningless), which the contract's item 4 forbids and the `gfx_displaylist` bone test catches. A DC2 pose that legitimately snaps (a motion cut) is a teleport per bone, so a cut reads as a cut.
- **HUD anchor ownership.** `present` (W4) and the sweeps share `dng_hud.cpp`-class units; the claims file settles it function by function, and `present` claims the top-level HUD draw functions first.
- **Display lists before W3 code exists.** `present-core` turns on recording in `mgBeginFrame`/`mgEndFrame` while `prog0`/`draw2d`/`fx-shadow` are still writing draws; its own acceptance uses synthetic draws through the seam, and the W3 end gate proves the real ones.
