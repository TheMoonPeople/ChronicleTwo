# Native memory safety ledger

The PC game builds from `port/src` and `port/include`. This ledger covers compiled native code and its file, script, save, and renderer inputs. The PS2 tree is unchanged. A passing build is not evidence that every input boundary is safe; the inventories below remain open until every location has been classified and the final instrumented runs pass.

## Verified fixes in the current migration

Effect defaults and reset initialize all base parameters, completion state, and counters; villager defaults use typed member initialization. Missing characters and absent villager workspaces are rejected before allocation.
- Map scripts use bounded path views and owned localized/reload paths. Loading retires the previous program, rejects invalid input or retired storage, checks the complete read extent and reserved arena guard, and publishes the program only after committing its allocation. Long logical paths, language fallback, reload, and exhausted or retired workspaces have dedicated tests; the long-path fixture uses an archive on both platforms.

- The broad initialization batch adds explicit initializers at 2,139 constructor, member, and local-record locations. The configured tidy pass covers all 434 port translation units with zero member-initialization findings; other compiler and tidy findings remain open. The project still carries its initialization, aliasing, and signed-wrap flags pending separate closure evidence.
- `CMenuKeyFunc` and `MENU_ASKMODE_PARA` reset through typed construction and assignment. Cursor and scroll fields use direct addresses, and command messages, colours, shading, and marks have separate typed arrays. The item-menu mark scan uses its actual eight-element extent, with checked message and cursor indices before command reads.
- Each `CGamePad` owns its recording vector and uses a host-sized frame index. Calibration clamps integer samples before arithmetic, and capture clamps them before byte conversion. Unused controller DMA buffers and the forwarding compatibility header are removed.
- `dc2::password` owns encoded text and decoded bytes, checks complete extents and overflowing base-58 groups, and performs checksum and scrambling arithmetic with explicit wire widths. Five reference encodings are preserved. Spheda passwords read nine hole scores without touching record padding. Fish-name keys are zero-padded, and invalid decoded item kinds are rejected before mutation.
- Render-test hook guards clear future callbacks and wait for an in-flight callback before borrowed probe storage is destroyed. The reproducing teardown case passes twenty sanitizer-backed iterations.

- `native/object/world/editmenu.cpp` now bounds analysis tables before reading them, sizes request and position storage to their defined limits, and keeps wrapped text in an initialized local buffer. `editdata.cpp` rejects out-of-range condition indices.
- `native/object/menu/menuop.cpp` no longer formats a filename using the same buffer as both source and destination. `menuaqua.cpp` checks a fish-race JSON count against actual arena capacity before placement construction and rejects negative race-fish indices; `NativeRecords.RaceFishCountsFitTheArenaAndIndicesStayInRange` exercises both cases.
- Event script loading checks the 32-byte map component before copying. Caption, message, fish-race, and map-jump fields are length-checked; sword-effect and script-object slots use typed array indices. The event and action test suites call the registered handlers with boundary values.
- Native `gameutil` uses count-sized mesh work storage and rejects invalid face indices; the unused 11-reference PS2 frame-link table is gone. Fixed-model face indices live in persistent model memory. Renderer and arena tests cover these lifetimes and alignment contracts.
- The native script loader receives actual program-byte spans and rejects malformed header, function, opcode, jump, string, and call extents. Registered callback tables use bounded typed views with checked numeric values and explicit text provenance; final instrumented validation remains open.
- The dungeon read buffer now exposes its live arena lease and reserves the renderer's region when placing short-lived file workspaces. Editor debug text uses owned strings and the editor's saved-data load copies only an exact, bounded record.
- `dc2::memory::CopyTrackedBytes` has an explicit destination/source API while retaining both texture metadata hooks. `dc2::log::PrintGame` is explicit and all production formats audited so far are literals. Bounded Shift-JIS helpers protect known fixed text fields.

These fixes do not close the unreviewed sites in the inventories.

## Script and character boundaries

Run-script and configuration callbacks use `RunArguments` and `TagArguments` views. Each view keeps its own slot extent, checked cursor, text-source spans, and explicit writable-slot span. Nested calls carry independent metadata. Registered tables have typed function signatures; the shared invocation functions catch malformed-argument errors from both semantic validation and callback execution. Run-script invocations require an exact operand count. Configuration tags keep their explicit count separately from the initialized prefix inherited from earlier tags.

Each `CScriptInterpreter` owns its retained slots and per-slot text at each callback depth. Assigning a new script changes the storage generation, so omitted slots cannot inherit another interpreter's values or a previous script's values. Production interpreter instances are automatic local objects; copying and moving interpreters is disabled because their metadata contains internal pointers. Regression fixtures cover alternating interpreters, nested access to an outer view, shorter tags, overwritten slots, and new-script resets.

Retained `ARG_LIST` nodes and declared `ARG_DATA` extents are checked against their live arena allocations before event handlers consume them. Numeric getters reject wrong kinds and non-finite conversions. Text getters establish allocation membership before looking for a terminator. Vector helpers validate all components and output references before writing a vector; event and monster callbacks use the same complete-vector write rule.

Character key and sequence builders retain typed entries until they can allocate and publish complete arrays, including their terminators. Sound cues cannot advance beyond the count declared by `SE_START`. Dynamic-animation copies check each host-sized allocation, and outline copies use the actual `COutLineDraw` type. Character effect pools use checked host-sized objects and arrays; `CEffectCtrl` has a defaulted trivial destructor because it owns no resources. The event effect heap descriptor has an ordinary owning lifetime and runs its arena-registry destructor when cleared.

Character stack partitions reserve their parent allocations before creating explicit child bindings. Disabled partition slots are empty. Event monster stacks identify their actual parent, and the event effect heap establishes the parent lease before rebinding its own heap view. Local work arrays and static sound arrays remain explicit external roots. The old model-pack tag table and its private parser chain have no readers; the active model-list loader reads native JSON directly.

Screen-effect captures keep explicit arena image leases, including bounded subviews when monochrome images share the global read buffer. Capture and draw paths reject retired storage before touching pixels. Screen byte arithmetic and texture-block offsets are checked, and the CPU tint loops operate only on verified RGBA extents. Photo capture passes actual array byte spans to the color and depth readback APIs.

Script byte readers check the source end before reading or comparing delimiters. Numeric tokens and converted command operands are range-checked before conversion; malformed or truncated binary tags cannot reuse retained arguments as a successful invocation. The unchecked pointer-only run/tag getters have no remaining callers and are removed. Native model-profile branches use the same checked argument and text views as registered handlers.

A focused core/unix/C++ Clang analyzer pass over the changed character, dynamic-animation, event, and monster-opcode units reported no diagnostics after the null, bounds, and vector-alias fixes. This is source-analysis evidence only; the final linked, optimized, and instrumented runtime gates below remain required.
