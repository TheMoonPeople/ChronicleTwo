## Both residuals have one cause

The 25 words are the player/fish saved-register exchange (retail keeps the
player in `s2` and the fish in `s1`) plus the placement-new branch pair
(retail `beqz v0` with `move s1,v0` in its delay slot; the draft copies first
and tests the copy).

An LLDB capture of the GPR allocator (`.private/nmmisc/fs/`, using the
`.private/nmsim/ra/` framework with helper mask `0x30`) reproduces the draft
exactly, and a simplify/colour simulation reproduces every captured colour.
Virtual registers: `scene` v32, `tex_manager` v45, player `chara` v44,
`message` v43, `save_data` v42, `fish_param` v41, `fish_item_no` v40, then the
fish pointer v37, then the load CSE temporaries (v36 `MotionBuff`, v34
`LanguageCode`, v33 `font_h`). User locals are numbered in reverse declaration
order; `fish_chara` has no number of its own. Copy propagation removes it, and
the new-expression result temporary (v37, numbered after every user local)
carries the object.

Renumbering only the fish pointer to lie between `chara` and `tex_manager`
(where `fish_chara` would be numbered if it survived) gives retail's
`chara = s2`, `fish = s1`, with no other register changing. Moving the player
below v37 does the same. Retail's branch shape (testing the call result in `v0`
and copying it into the saved register in the delay slot) is that same IR: the
declared variable is kept apart from the tested allocation result. The
permutation is therefore part of the known placement-new blocker, not a
separate lifetime problem, and work on this function stops here as the brief
directs.
