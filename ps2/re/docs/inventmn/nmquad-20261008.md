## What retail's base needs

Retail computes `this + 0xD60` inside the loop body: loop-invariant code
motion hoists it into each unrolled copy's preheader after the three
induction initialisations, and again before the two-photo remainder
(`+0x94`). A named row pointer assigned before the loop computes it once,
before the inductions (the 13-word residual). Every typed expression of
the array inside the loop lets MWCC fold the `0xD60` member offset into
the strength-reduced offsets (34 words). Only a cast node on the decayed
array keeps the base opaque.

| Loop-body form | Result |
|---|---|
| `photo_work[index]` (control) | 34/48 |
| `((char (*)[0x2000]) photo_work)[index]` (same-type cast) | **0/48** |
| `(char *) photo_work + index * 0x2000` (byte arithmetic, known) | 0/48 |
| `(&photo_work[0])[index]` | 34/48 |
| `(photo_work + 0)[index]` | 34/48 |
| `(&*photo_work)[index]` | 34/48 |
| `(photo_work + index)[0]` | 34/48 |
| `*(&photo_work[0] + index)` | 34/48 |
| `&(&photo_work[0])[index][0]` | 34/48 |
| Function-scope `char (&work)[30][0x2000] = photo_work;`, `work[index]` | 14/48 |
| The same reference declared in the loop body | 42/48 |
| Loop-body `char (&row)[0x2000] = photo_work[index]; ... = row;` | 34/48 |
| `char (*work)[30][0x2000] = &photo_work;` after the index, `(*work)[index]` | 13/48 |

The same-type row-pointer cast has no type pun, byte arithmetic, helper
or local, and reproduces all 48 words. It is still a no-op cast whose only
effect is code generation, so it is recorded as a policy candidate rather
than applied: compare menudraw's `CommonBoardDraw`, which matched only after
its inherited no-op `(int)` casts were removed. Reconsider if a real type
difference (for example a 16-bit pixel element type for the 64x64 photo
rows, which would make a row-pointer conversion genuine) is established for
`photo_work` and `USER_PICTURE_INFO::image`.
