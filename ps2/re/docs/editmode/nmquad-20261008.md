## Retained: the key direction reuses the stick values

The digital-key branch overrides the analog direction and then applies the
same rotation as the stick path, with the camera angle snapped to a quarter
turn. Writing it with the existing `stick_x`/`stick_y` locals instead of
separate `key_x`/`key_z` locals (and without the three unused float
declarations) gives retail's FPR assignment: `stick_y` `$f24`, `stick_x`
`$f23`, axis cosine `$f22`, axis sine `$f20`. As later webs of reused
variables, the two values are coloured after the axis locals.

The retained form keeps the stick formula's operand order
(`move_x = stick_x * axis_cos + stick_y * axis_sin`). The whole axis region
(`+0x314..+0x400`) now matches.

## Remaining: camera-query arguments and the lower corner

With the row, 63 words remain: `GetGeoCheckCamCol`'s `a0`/`a1` setup at
`+0xB68/+0xB70` and the ground query from `+0xD2C`.

- Passing a real `mgVu0FBOX box` (`box.max`/`box.min`, `GetGeoCheckCamCol(map,
  box, ...)`) restores retail's argument order exactly (`move a0,s2`,
  `addiu v0,sp,404`, `addiu a1,sp,400`, `a2`, `a3`). In the cast form the box
  address is shared with the earlier `box_max[...]` accesses and set up first.
  Un-nesting the call, `(CMap *) map` and `> -1` do not move it.
- Retail holds the lower-corner pointer (`sp+416`) in `s5` from `+0x77C`
  through `+0xDA8`: the first copy, the three `[0]` adjustments, the
  `mgVectorMaxMin` argument and the ground-query copy. Only `[1]`/`[2]` use
  fresh `sp+420`/`sp+424` addresses. MWCC propagates a pointer with a single
  definition from a local's address into every use and rematerialises it
  (`addiu v0,sp,416`), whether the definition is a declaration initialiser,
  `&box.min[0]`, `float *const`, or an embedded assignment. The draft's
  second assignment at the ground query blocks propagation but creates a
  separate web (`t2`), so `s5` falls to the ground count.

## Why the single lower-corner web is lost

Toy compiles (`.private/nmquad/toy/p1..p4`) show that MWCC keeps a
single-definition pointer to a local array in a saved register across
calls, however long the range; it does not propagate it at IR level. A
separate `p = b;` statement is forward-substituted within its basic block,
while an embedded `(p = b)` is not; a web that crosses no call is
rematerialised. In EditMode the single web (`+0x77C..+0xDA8`) is therefore
a register-allocation spill: with it, `poly_count` and the ground count take
`s5`, and every use rematerialises `sp+416`. Retail colours the same web
`s5` and gives `poly_count` `s6` and the ground count `s4`; only six saved
registers are live across the camera block, so retail's choice is the
simplify order (degree below 25 before the node becomes a spill
candidate), not a register shortage.

A redundant `box_low = box_min;` statement placed just before the
`wall_parts` camera override (cast-box draft) gives **14/1912** with the
row: the ground-query corner then lives in a saved register (`s4`), with a
new `addiu s4,sp,416` in the delay slot at `+0xC5C` where retail has `nop`,
and `s4`/`s5` exchanged with the ground count and map offset. The same
statement before the `ePartsCurPos` copy or after `GetEditAngle` gives 66,
before the limit-height query 106. That statement has no source meaning
beyond code generation and is not retained; it shows that retail's corner
pointer is one web that survives the camera block. With the direct scene
calls it gives 131-199.

A low-pressure toy with the typed box (`.private/nmquad/toy/p5`) keeps
`p = box.min` in a saved register, so the typed box's loss of even the
first corner web in EditMode is again an allocation-order effect. On the
current draft the direct scene calls give 177 (camera), 222 (map) and 245
(both) with the row; `CScene` has no inline accessor that would make the
wrappers a real source identity.

## The typed box needs no corner alias

A real `mgVu0FBOX box` written without any `box_low` pointer (`box.min`
in the copies, the `[0]` adjustments and the `mgVectorMaxMin` argument) is
the natural candidate. `box.max` is the box's own address and folds into
`lwc1 $f0,400(sp)`, but `box.min` is `&box + 16`, which MWCC turns into one
common subexpression across all three sites. Toy compiles
(`.private/nmquad/toy/p6`, `p7`) keep that CSE in a saved register across
any number of calls, in small and in `0x30000`-byte frames, producing code
identical to the explicit pointer. The same mechanism explains the
`addiu v0,sp,X; sw 0(v0)` element stores throughout EditMode: an element
address used at several sites (`box.max[1]`, `box.max[2]`, `box.min[1]`,
`box.min[2]`, `new_pos[1]`) is a cross-site CSE that the allocator spilled
and rematerialised, while a single-site element folds (`start_pos[1]` as
`sw v1,468(sp)`; toy `p11`).

With the row, the alias-free typed box (`.private/nmquad/edm/tn0.cpp`) is
`0x1DEC` bytes. A register-aware aligned comparison
(`.private/nmquad/aldiff.py`) leaves exactly these differences: the `box.min`
CSE is rematerialised at its nine uses instead of living in `s5`; the
dependent `poly_count`, ground count and map offset take `s5`, `s5` and `s4`
instead of `s6`, `s4` and `s5`; and one `addiu a3,sp,400` is scheduled two
slots earlier at the ground copy. The camera-query arguments, every other
register and every other instruction match retail.

The CSE is spilled although `s6` is free across its whole range, so the
allocator spills its choice rather than colouring optimistically. Toys
`p8`/`p9` (nine saved registers `s0`–`s8`) show the CSE's nine references
outweighing a long-lived `int` with up to four references and losing to
one with five, so a rematerialisable CSE counts about half per reference.
Diagnostics on `tn0`, none of them source candidates:

| Each of 1,194 single-statement moves (up to eight statements either way) in the collision-box source | only moves that put a `box.min` use inside the ground loop keep it, spilling `scene` |
| Each of 287 single-statement deletions across EditMode | only removing `edit_name = info->edit_name;` keeps it (1,392 words, `0x1D74`) |
| `ground_count`/`next_poly` initialised just before the ground loop (either order), split or in the `for` | `0x1DEC`; the schedule is unchanged |
| `edit_name` declared at its first assignment or after `map`; assignment embedded in its test | `0x1DEC` |
| `edit_name = NULL;` moved from the turn-step setup to just before the `info->edit_name` read | `0x1DE4`; retail stores the null to `edit_name`'s slot (`sp+272`) at `+0x508`, so its definition is early |

A rematerialisable CSE's references barely count in the spill choice: no
number of straight-line uses keeps it, while one use inside a loop does.
Toy `p13` (seven long-lived `int`s, the CSE and up to nine short
call-crossing values) keeps the CSE in a saved register, so short
neighbours are simplified before it. At the deciding step, the CSE and `scene` are the two cheapest remaining
nodes, and retail keeps both. Retail's interference graph must therefore
have had less pressure there than this source gives. Everything else in
the final code is identical, so the difference is not visible in retail's
instructions.
