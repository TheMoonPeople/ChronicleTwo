# menuchr hygiene pass (2026-10-09)

Scope: `CMenuCostumeSel::Draw`, `CMenuChrCngMenu::EnterDataMenu`,
`CMenuMosSelect::KeyStep`, `MenuCharaChangeStarDraw`,
`MenuItemCharaDataLoadEndCheckAfter`. Checked with a PAL build
(`SCES_511.90: OK`) and `check_objects.py` (149/149).

## New name
- `MOS_SELECT_PAGE` (menuchr.cpp, next to `MOS_SELECT_COMMAND_MSG`) for the
  monster box's `key_arg_no`. KeyStep's `switch (key_arg_no)`: 0 moves over
  the badges (KeyNormalMode), 1 runs the badge command window and its steps,
  2 cycles `view_monster` through the forms with L/R. Action 500
  (バッジ選択に戻る, "return to badge selection") sets 0, action 600
  (バッジコマンド, "badge command") sets 1, action 20 (ステータスを見る,
  "view status") sets 2; `key_arg_no == 2` fades the info window in.

## Changed
- `CMenuCostumeSel::Draw`: `mode == MENU_ASK_MODE_NONE` (its KeyStep uses
  1 opening, 2 fading out, 0 taking keys: `MENU_ASK_MODE_OPEN/CLOSE/NONE`).
- `CMenuMosSelect::KeyStep`: `switch (mode)` and its assignments use
  `MENU_ASK_MODE_*`; 10 `MenuSePlay` sounds use `SYSTEM_SE_*`; the yes/no
  answers use `MES_YESNO_*`; `MsgPreset(MENU_SCRIPT_MES_YESNO/ITEMCMD)`;
  `MenuArg.result[0] = USER_CHARA_MONSTER` (with end code 1 menumain passes
  it to `SetActiveChrNo`), `CheckEnableCharaChange(USER_CHARA_MONSTER, ...)`
  and the monster `SetupUnitMan` character; `now_mode == MENU_MODE_ITEM`,
  `GetMenuLoopType() == MENU_LOOP_TOWN`; `MOS_SELECT_PAGE_*` for
  `key_arg_no`.

## Monster box actions and command steps
- `MosSelectAction` (local to `CMenuMosSelect::KeyStep`, like
  `CMenuTreeMap::Step`'s `TreeMapAction`): the keys request an action that
  the closing `switch (action)` runs. 5 plays the cancel sound; 10 closes
  the box with `MOS_SELECT_RESULT_CHANGE` and Monica's new form; 11 runs
  `NOT_変化` ("cannot transform") and moves to step 1; 12 fills the form
  list (step 20); 20 runs ステータスを見る and opens the status page; 30 fills
  the class-change list (step 10); 500 runs バッジ選択に戻る; 600 runs
  バッジコマンド and builds the command window; 1000 closes the box with
  `MOS_SELECT_RESULT_CLOSE`.
- `MOS_SELECT_COMMAND_STEP` (menuchr.cpp) for `step` on the command page:
  0 command choice; 1 error message (any button returns to 0); 10
  class-change list (decide runs クラスチェンジ？ and asks yes/no); 11 yes/no
  (yes runs クラスチェンジ！ and loads `SP_045.snd`/`mos_chn.chr`, no returns to
  10); 12 the effect plays and the badge moves up a class; 13 the
  クラスチェンジ終了MSG message (then the モンスターしずく attach reward);
  14 the reward message (the last class also gives `ghobitbl[select]` with
  `GET_LAST`); 15 the last reward message; 20 the transform form list.
- Left literal: `MenuSePlay(0x10)` (transform), `MenuSePlay(2)` (status page
  open), `MenuSePlay(0x1E)` (class change done): no other evidence ties
  those system sounds to one meaning. `BuildUpWeaponInfo.mode` is 0 hidden /
  1 list shown (a boolean). `MenuLoadInfo.mode = 2` is the shared load mode
  noted above.
