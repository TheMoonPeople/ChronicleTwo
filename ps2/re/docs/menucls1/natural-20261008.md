# menucls1 natural access (2026-10-08 night)

Byte-identical object (`check_objects menucls1`: 0x2B00 bytes, 304 relocations).

## Replaced
- `CMenuFont::CMenuFont`, `MenuMesInit`: `*(int *) &float_field = 0` becomes `= 0.0f` for
  `offset_x`, `offset_y`, `fade` and `reveal`; MWCC stores `$zero` directly for a float zero too.
- Weapon-defence item use: the `(u16)` / `(u16 &)` casts on `CHARA_DATA::defence` are dropped now
  that the field is `u16` (userdata).
- `CDC2Mes::put_centering` is `s8`: both `SetPutPos` overloads load it
  with `lb` and test it against zero; the `(signed char *)` view and the `(s8)` conversion are dropped.
  Its stores (menucls1, editmenu, menusys) write 0 or 1 with `sb`.
- `CMenuItemUse::CheckItemUseEnable`: the `int target_data[2]` stack target is a
  `CItemUseTarget` declared after the NULL checks; its inline constructor is the `-1` store into
  `type` that preceded `SetPtr`.
- `CMenuMoveItem::AttachForm`: `GetFormInfo` already returns `CMenuPosDataForm *`.

## Kept
- `CMenuItemUse::UseItem(CGameDataUsed *, int, void *)`: the stack target stays a `u64` viewed as
  `CItemUseTarget`. A `CItemUseTarget` local runs the inline constructor, adding a
  `li v0,-1; sw v0,88(sp)` before `SetPtr` that retail does not have.
