# automap: natural typed access (2026-10-08)

## Replaced

- `CMiniMapSymbol::SetMapInfo`, `CMiniMapSymbol::Draw` and
  `CAutoMapGen::Build` test the part names with `name[0]` instead of
  `*(s8 *) part->name`; `CMapParts::name` is already `char`.
- `CAutoMapGen::SetupRoomInfo`: `room_info = new (mem->Alloc(0x62)) AUTOMAP_ROOM_INFO[64]`
  replaces the cast `operator new[](0x600, ...)` call.

## Kept

- `CAutoMapGen::CreatTermParts`: the candidate cell and its upper and lower
  neighbours are addressed as `(u8 *) grid + y_off + x_off` with byte offsets
  computed once, and the room number is read back through the same offsets
  after the loop. `grid[y * row_width + x]` adds the indices before scaling.
  `grid + y * row_width + x` scales row and column separately like retail
  but evaluates the row first, so the column offset and the cell pointer
  exchange registers (`a0`/`a1`) throughout the loop.
- `_ROOM_SIZE`: the cell table contains two `s16` values per cell (part index and
  attribute), so `width * height * 4` bytes do form `s16[width * height * 2]`.
  The typed placement-new candidate using that element count compiles but its
  complete object fails `_ROOM_SIZE`'s byte comparison at 0x1D6BE9 (retail body
  0xB4). The alternative `s16[bytes / sizeof(s16)]` also fails, first at
  0x1D6BC8, and adds four bytes to the unit with shifted call/data relocations.
  The explicit `operator new[](bytes, ...)` form stays for its exact code,
  rather than because the data cannot be represented as a typed array.
