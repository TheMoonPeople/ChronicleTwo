# mg_visual: natural typed access (2026-10-08)

## Replaced

- `mgCVisualMDT::DataAssignMDT` and `mgCVisualFixMDT::DataAssignMDT`: the
  face section is read through `MDT_FACES` (`faces->prim_num`, first
  `FACES_ID` at `faces + 1`) instead of `*(int *) (table + 8)` and
  `table + 0x10`.
- `mgCVisualFixMDT::DataAssignMDT`: the per-face scratch stack is a plain
  `mgCMemory` (its constructor runs `Init`), replacing the file-local
  `VisualScratchMemory` overlay and the `(mgCMemory *) &scratch` casts. The
  overlay struct is removed.
- The face packet address is `(int) &memory->stack[memory->stack_used]`
  instead of reading `stack` and `stack_used` through the overlay.
- The DMA tag words go to `mgCFace::packet_tag_word[n]`, the four-word view
  of `packet_tag` in an anonymous union (visualmotion writes it the same way),
  instead of `((int *) part)[8..11]` or `((u_int *) &part->packet_tag)[n]`; the
  first word is `size | MG_DMA_REF`. The word stores compile as before
  (`.private/fixes-r3c/b3-*.log`).
- `mgCVisualMDT::CopyMDTDataPointer`: the vertex array cast is spelled
  `(sceVu0FVECTOR *)` like the other sections.
- `mgCVisualMDT::CreatePacket` and `mgCVisualFixMDT::CreatePacket`: after the end tag the cursor
  advances with `cursor += 16`, like the other tags, instead of `(u_char *) (end_tag + 4)`.
- `mgCDrawManager::packet_memory`/`data_memory` are already `mgCMemory *`; the same-type casts
  in `mgCVisualMDT::Draw` and both `CreatePacket` functions are dropped.
- Both `CreatePacket` functions read `info->attr->program_mode`; `mgRENDER_INFO::attr` is
  already `mgCFrameAttr *`.
- `mgCVisualMDT::Draw`: `texture_manager` is already `mgCTextureManager *`, and the scratch
  buffer converts to `void *` implicitly.
- `mgCVisualMDT::CreateFace`: both face groups are `new (memory->Alloc(4)) mgFACE_GROUP` instead of
  cast `operator new(sizeof(mgFACE_GROUP), ...)` calls.

## Kept

- `CopyMDTData` and `CopyMDTDataPointer` locate each section from the
  serialized `*_ofs` byte offsets. In `CopyMDTDataPointer` the section
  addresses are integers; pointer-form sums reorder the address arithmetic.
- `mgCVisualFixMDT::CreatePacket` reuses the `manager` parameter to hold the
  packet start; a separate `u_int *packet_start` local swaps `this`/`manager` between `s0`/`s1`
  and moves the start into `s2`, where retail keeps it in `manager`'s `s0`. The packet builders step `u_char` cursors over DMA and VIF
  data and address data through its uncached mirror as integers.
- `mgCVisualMDT::CreateRenderInfoPacket` writes matrices into the packet through
  `(float (*)[4]) &write[4]`: the packet is a `u_int` word stream, and each matrix lands as
  four quadwords right after the VIF UNPACK code word that announces it (`write[0..3]`), so the
  matrix functions receive the packet words as a `float[4]` row array.
- `SetMaterialRef`, `mgSetPkTEX0` and `SetData6` keep `*(u_long128 *)` on both sides of their
  quadword packet copies (accepted convention).
- `CreatePacket` (both): data addresses are formed as `data_cursor | 0x20000000` (uncached
  segment) and packet sizes as `((int) cursor - (int) node->packet) / 16`; DMA address and
  quadword-count arithmetic on integer addresses.
- `mgCVisualMDT::CreateFace`: `switch ((int) out_face)` with `case 0` stays; `if (out_face != NULL)`
  changes the branch layout (0x14 bytes shorter).
