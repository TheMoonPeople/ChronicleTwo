# menucommon: natural typed access (2026-10-08)

## Replaced

- `_MENU_FORM_VIBECNT`: the second argument slot is a typed
  `SPI_STACK *next_slot = stack + 1`, matching the file's other two-argument
  handlers, instead of a `char *` holding `(char *) (stack + 1)` and a cast back.
- `_MENU_ITEM_CHECKMARK`: the texture info number is the value conversion
  `(s8) MenuCommonInfo->tex_block[0]` instead of a `signed char` view of the
  `int`'s first byte; both load the byte with `lb`.
- `_MENU_FORM_PARTNUM`: the new parts are initialised as
  `&menu_formPt->parts[i]` in a `for` loop instead of
  `(MENUFORMPARTS_TYPE *) ((unsigned int) menu_formPt->parts + offset)`.
- The `_MENU_FORM_*`/`_MENU_EXE_FORM_*` opcodes use `GetFormInfo`'s `CMenuPosDataForm *` result
  without a same-type cast (9 opcodes).
- `MenuCommonReadData`: each file loads at `memory->stack + memory->stack_used` instead of
  `(u_long128 *) (memory->stack_bytes + memory->stack_used * 16)`.

## Kept

- `MenuCommonReadData` walks the name list with a byte offset,
  `*(char **) ((u8 *) names + i)` with `i += 4`. Retail keeps the list base and
  a byte offset in separate registers (`addu v0,s4,s1`). Both `names[i]` with
  `i++` in a `while` loop and the same with the locals' declaration order
  swapped produce the same instructions with the offset and `size` registers
  exchanged (`s1`/`s2`). A `for` loop moves the increment after `Align64` and
  reorders the loop tail.
- `_MENU_FORM_MALLOC`: `(CMenuPosDataForm *) operator new[](bytes, block)`. With
  `new (block) CMenuPosDataForm[count]` the byte count is no longer kept in a saved register
  (`s1`), so the frame shrinks from 0x30 to 0x20 bytes.
