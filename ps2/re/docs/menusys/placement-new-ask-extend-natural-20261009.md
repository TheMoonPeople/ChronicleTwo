## Source and retail semantics

The only close request increment in the best specimen is cancellation; acknowledgement still directly assigns one. The close local remains the same `int close = 0`, with no added state or purpose. Each invocation selects one step case, and the two requests are mutually exclusive, so increment executes at most once and the common equality-to-one cleanup preserves all possible values. Retail uses direct LI one, not an explicit increment. `close-flag-evidence.md` contains the complete s7 census and distinguishes callee-save SQ/LQ from local storage and the byte rotation-global store.

Natural statics, actual inline literals, genuine constructor APIs/allocation size, original fields/headers and frame-attribute pointers are retained. The count-first comparison expresses the same selection bound and restores the retail count load and comparison instructions. OR-with-one controls preserve flag semantics but leave 174 positional words.

## Concrete blocker and bounded hypotheses

The best control restores the retail initial guard delay nop, manager stack slot `sp+0xC0`, form slot `sp+0xD0`, and reading in `s8`. Remaining code assigns close/message/name to `s5/s6/s7`, versus retail `s7/s5/s6`. Cancellation still emits `ADDIU s5,s5,1` instead of retail direct LI; its block is four bytes shorter, acknowledgement/global-byte scheduling differs, and the step-5 reset lacks the retail call delay-slot SH, making the total native symbol four bytes larger. Later model-file/new-item/texture-block/texture-manager lifetimes also differ: retail spills the file and retains the actual manager, while this source retains the file and rematerializes the manager. All exact offset/word changes are saved in the best diff and aligned receipt.

The single-site flag, prefix/postfix, OR flag and comparison controls exhaust the bounded follow-up. A future investigation could use actual message/file API lifetime evidence to distinguish the remaining register choices, but no recovered counting purpose, dummy state, register hint or invented steering helper is justified. The required fresh m2c run remains saved with its established jump-table naming failure; assembly is unchanged.

## Acceptance limits and reproduction

The best specimen is a native diagnostic only and has not been given a complete wrapper acceptance run. Prior private wrappers establish that the genuine 29-row control passes zero complete-object failures, while the minimal and natural IsAskExtend promotions fail with 752 and 1303 failures respectively, including shifted jump-table/literal/static binding and their cascading relocations. Their failed receipts are retained; these are not acceptance evidence for the best specimen. No tracked file, shared header, profile, image or root build directory was edited.

`ask-residual-freeze.json` saves every source/profile/object hash, all native positional and shifted counts, nonselected audit results, the exact outer H/image command, and the current tracked snapshot. `proposals/ask-residual-frozen-source.patch` is a diagnostic source diff against the current tracked menusys file; the guard is retained. `proposals/ask-residual-frozen-row.delta.json` contains only the private row, so newer root rows cannot be removed by applying an obsolete full-profile patch.
