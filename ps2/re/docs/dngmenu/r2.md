# dngmenu r2 on the merged Satan's Fiddle base

This is a historical probe record. The current native/guarded status is in
[notes.md](notes.md#current-assembly-gaps); later exact matches are documented
in [night-20261008.md](night-20261008.md).

The lane starts at `2f71f10c530becb9ed222253646514480b9c087d`, integration
build i15, using `chronicletwo_dev:sf-24490d0` and `JOBS=3`.
A clean build reproduces i15 before source changes: PAL `.text` differs by
0x26 bytes, all other file-backed sections, main length, and BSS/memory end
match. Only `nd_meswin` and `actscript` fail the complete object checker
(147/149). Coverage is 6,681 matched, 174 guarded, 15 asm-only, 2 fuzzy.

All requested targets were recompiled through the SF adapter with the actual
profile and canonical flags, plus `UNMATCHING`/`NONMATCHING` for diagnostic
measurement. Plain-wibo `draft.sh` results are retained separately. Neither
instrument is promotion authority: each promotion removes its guard manually,
compiles with `mwccgap.sh`, runs section fixup, and passes the complete object
checker including resolved relocations. No promotion-ledger entry or SF row
was added. Shared headers and `dng_main` were untouched.

## Accepted native functions

`CheckGeoramaMateria` reuses the group-search index for the subsequent item
loop. The search is finished before that reuse; the floor traversal and two
attribute-filter passes retain their existing separate index. This natural
lifetime makes the compiler's item counter/offset registers agree with retail.
It changes 6/112 differing words to zero. Its first complete-unit receipt
passes 0x8BD0 allocated bytes and 1,131 relocations.

`CMenuTreeMap::InitEnd` uses a snapshot of the signed maximum floor count
across lookup calls. Loader locals are declared as block, texture-manager
pointer, and map image, while values are still initialized after `GetPackFile`.
This preserves the manager across the unrelated texture-loader call and
produces retail's saved-register reuse. The complete frame is 0xA0F0.
The lower and upper room bounds are separate checks. Selected sub/boss rooms
are tested separately, sub first, and assigned as marked cell then active
floor. A two-float coordinate pair receives the two X offsets before copying
into the cursor. The successful file loader supplies its output size, so that
local needs no zero initialization. The final state enables `cursor_view`,
not the money board. These changes make all 224 words exact, without profile
calibration. The two-promotion complete-unit receipt passes 0x8BD0 allocated
bytes and 1,146 relocations.

The register map in the exact InitEnd is block s0, manager s1, image s2, read
record s5; later active room s6, marked cell s1, floor bound s2, loop index s3,
and Y-element address s0. All are compiler-generated from ordinary C++ locals.

## Retained guarded corrections

`CheckIsViewMove` is now supplied by upstream's exact source and GPR helper
seed `0x30`; the former X/Y-copy park is superseded. `MsgInit` remains
guarded: its recorded actual-unit trial fails at 0x1F1450 and the height
relocation at +0x14C. That integer scheduling is outside the floating
annotation selectors.

`DrawRoot` now selects all four event tint values in one branch after their
menu defaults, as retail does. `DrawRoomOne` restores the glyph destination
rectangle Set call at 0x1EDD28 and calculates unvisited-overlay corner
coordinates before the drawing calls. The far corner uses the retained
origin plus 20/30, preserving retail's floating operation order.

The `medal_xytbl_1736` reads in `DrawDngRoomInfo` are signed halfwords, not
packed rectangle words. Retail loads offsets 0, 4, 6, and 8 and assigns only
the highlight rectangle's left coordinate. The retained typed array loads
indices 0, 2, 3, and 4 for timed clear, fishing, spheda, and the final medal row;
their X values are 168, 212, 234, and 146. Its top, width, and height remain
0, 22, and 22. Index 1 contains 190 and is unused by this function. The retail
data reservation remains unchanged. Correcting the omitted UV reads increases
the still-mismatching body's size; it does not establish native matching.

`LoadDngInfo` now retains remaining arena capacity before obtaining its top
pointer and rounds unsigned loaded byte lengths up by quadword quotient and
remainder. A 64-byte filename scratch buffer replaces the 128-byte draft
buffer, reproducing the 0x160 frame. This capacity is a layout hypothesis;
the filename fits either buffer, and the remaining local offsets/path logic
still require matching before promotion.

The three Menu Step initialization flags are signed bytes, matching retail
`lb`. Menu Draw sets its integer help state in a short-circuit branch, removing
boolean materialization. Its raw differing-word count rises because subsequent
instruction offsets shift; the new help block follows retail control flow.
FreeMap Draw encloses drawing in the positive active/alpha/texture condition,
using `!(alpha <= 0)` to preserve unordered-float behavior. Its texture check
now shares the function exit.

## Useful negative results

For view clipping, making the first clip a conditional expression adds a
branch and grows the body to 0x144. Testing the clip local, retaining the float
input, and changing to mutable input parameters do not fix the initial copies.
A named first-line X coordinate in MsgInit leaves 7/116 words unchanged.

For georama drawing, moving the right-column declaration earlier leaves the
same wrong spill and 0x404 body. For InitEnd, a manager binding alone gives
217/224 differing words; revisiting it was justified only after the missing
floor-count live range made the frame exact. This combination then matches
all loader setup bytes. Do not repeat the isolated manager experiment.

## Final acceptance

The final incremental build, standalone verifier, complete object checker,
and refreshed ctx/objdiff report preserve i15 exactly. PAL `.text` still
has the same 0x26-byte mismatch starting at 0x15C5AD; all other sections,
main length, and BSS end 0x1F64A00 match. All ten loaded file-backed sections
are byte-identical to the clean lane baseline. Object checks are 147/149;
the failure lists are unchanged: nd_meswin DrawMesWin at 0x15C5AD and
actscript _SHOT at 0x2D5DB2. The final dngmenu object passes 0x8BD0 bytes
and 1,146 relocations. Both promoted symbols score 100% in objdiff.

Coverage is 6,683 matched / 172 guarded / 15 asm-only / 2 fuzzy, and dngmenu
is 36/11/1/0. Comparing all 6,872 function classifications changes exactly
the two named promotions from guarded to matched. No other function changes.
The known verifier/checker failures therefore remain expected nonzero exits;
this is acceptance against i15, not an all-green retail build.
