# dngmenu: MsgInit rejected forms

The matching form is in [notes.md](notes.md): the first line's screen X and
half line width are named values updated in place, so the height load keeps
`v1` and retail's load order follows. The forms below all leave the same seven
differing words at +0x140..+0x15C, where retail loads screen height, screen
width and first-line width in that order and subtracts fifty before the two
shifts.

## Layout

MsgInit attaches the tree message data to all eight `CDC2Mes` windows,
configures the shared buffers, runs `MSG_INIT`, appends the opening-mode
prompt, and places its two lines near the screen bottom. The second line moves
to X=600 while saving is inactive. `CDC2Mes` has stride `0x2A50`, line widths
are signed words, and line positions and their enable fields are word arrays.
The shared Y stays a word until the final halfword `TreeMapSaveDispY` store;
short/long-coordinate forms must not redefine these field widths.

## Forms that leave seven words

- `TreeMapSaveDispY` as a `static short` definition (retail is a LOCAL two-byte
  object). `CheckDngTreeMapFuncType`, `GetMenuMainMessageBuffer`, and
  `GetSystemMesBuffer` are GLOBAL and cannot be localized.
- An unsigned Y. A long Y grows to `0x1D8`.
- Three separate input snapshots and all input initialization orders; caching
  inputs does not enforce retail's load schedule. A separate baseline
  subtraction.
- A typed first-position pair initialized Y then X. An aggregate X/Y
  initializer grows to `0x1EC`. Access through the `ClsMes` base reference.
- Scoped level two grows to `0x210`. Disabling lifetime optimization or
  pointer analysis leaves seven. Size optimization gives 50/116 at `0x1CC`.
- Immutable input snapshots, an immutable screen-height copy used by a
  compound Y subtraction, and a const message pointer. An immutable width copy
  with compound X updates gives eight; one shared X variable for both line
  calculations gives ten.
- `CDC2Mes::SetMovePosGyou` for line 0, line 1, the 600 override, or any
  combination; `y` bound inside the first setter call; a named X local passed
  to the setter.
- `y` declared at function top, `const int y`, `y` in its own block, a named X
  declared before `y`, X0 as `-(w0 >> 1) + (W >> 2)`, `(W >> 2) * 1` or
  `(W >> 1) >> 1`. `int x = W >> 2; x -= w0 >> 1;` gives eight; field compound
  `line_pos[0][0] -= ...` gives 0x1D8; `line_pos[1][1] = line_pos[0][1]` gives
  0x1D4; `line_pos[0][1] = y = H - 50` gives eight; an early save-label store
  gives 23; the dngmenu GPR helper mask is insensitive (0 to 0xFFF0 all seven).

Floating evaluate-first selectors have no applicable identity in this integer
calculation.
