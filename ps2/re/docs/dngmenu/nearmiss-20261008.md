## Evidence and layout

Fresh `decompile.sh --no-cache --no-switches` output confirms the documented
initialization and positioning behavior. It attaches the tree message data
to all eight `CDC2Mes` windows, configures the shared buffers, runs `MSG_INIT`,
appends the opening-mode prompt, and places its two lines near the screen
bottom. The second line moves to X=600 while saving is inactive.

Existing types are sufficient: `CDC2Mes` has stride `0x2A50`, line widths
are signed words, and line positions and their enable fields are word arrays.
The shared Y stays a word until the final halfword `TreeMapSaveDispY` store.
The short/long-coordinate hypotheses must not redefine these field widths.

The canonical private entry compile uses mwccgap, section fixup and complete
byte/relocation checking. Other source probes use the SF adapter with the
same flags and logical `dngmenu.cpp` identity. Scores mask relocation fields
and pad to the manifest extent; no nonzero score qualifies as promotion.

## New hypotheses

- Retail `TreeMapSaveDispY` is a LOCAL two-byte object. A natural private
  `static short` definition replacing its BSS marker still gives seven.
  `CheckDngTreeMapFuncType`, `GetMenuMainMessageBuffer`, and
  `GetSystemMesBuffer` are GLOBAL; they cannot be localized as helper fixes.
- An unsigned Y retains seven. A long Y grows to `0x1D8`, consistent with
  long's different width in this compiler; no width change is retained.
- Three separate input snapshots and the remaining input initialization
  orders all retain seven. Caching inputs therefore does not enforce retail's
  load schedule. A separate baseline subtraction also retains seven.
- A typed first-position pair initialized Y then X gives seven. An aggregate
  X/Y initializer grows to `0x1EC`. Access through the actual `ClsMes` base
  reference leaves seven.
- Scoped level two grows to `0x210`. Disabling lifetime optimization or
  pointer analysis retains seven. Size optimization gives 50/116 at `0x1CC`.
  None of these controls is retained.

The unchanged difference is `+0x140..+0x15C`. Retail loads screen height,
screen width and first-line width in that order, then subtracts fifty before
the two shifts. Native code reads first-line width first and subtracts the
height offset after the X subtraction. First X/Y/enable stores and the
second line's established code agree in the seven-word candidates.

The canonical entry object reports target code bytes at `0x001F1450` and the
shifted height relocation at `+0x14C`. Floating evaluate-first selectors have
no applicable identity in this integer calculation; no helper is invented
to manufacture one. Retry requires a new natural positioning form or an
explained compiler scheduling difference, rather than repeating these
input-cache or width probes.
