## Round 1 (nminv): DrawFishParam promoted

`DrawFishParam__FiiP10mgCTextureP13CGameDataUsed` is native and exact. Its
declared retail and native symbol sizes are 0xAF8 bytes. The 0xB00 aligned
reservation includes two padding `nop`s that the complete object also emits. Complete-unit check: menuaqua object
`0x11C2C` bytes, 3,263 relocations; 149/149 objects pass; SCES_511.90 OK
with 6,758 perfect functions.

The retail panel code follows one layout style throughout, and each
difference from the earlier draft traced back to it:

- **Float-to-int conversions are casts, not explicit `fptosi` calls.**
  MWCC can CSE a repeated `(int) (fy + cy)` cast. Retail does this for the
  size and weight boards (`move s3,v0; move s1,v0` after one conversion) and
  for the name board / name `y` (`move a2,v0` plus the `name_y` spill).
  Under the unit's 0x30 helper mask, the 69.0 temporary before the
  unknown-weight conversion takes `a2` instead of `a0`. In the background
  loop, casts are evaluated left to right (x first, kept in `s3`); explicit
  calls go right to left.
- **Cell positions use the running `cx`/`cy` offsets.** After the parameter
  cells, `cx = 0x16; cy += 0x16;` positions the size board, and
  `cx += 0x8A` positions the weight board. With `fx + cx`, MWCC keeps
  retail's `fx`-first `add.s` operand order and recomputes `fx + cx` at
  each use. With the literal `fx + 160.0f`, it puts the constant first and
  CSEs the sum into `f22`.
- **Shared `bx`/`by` positions.** The size board, weight board, weight-unit
  label and unknown-weight glyphs all reuse `bx` (`s2`).
  `int wy = by + 2;` is declared before the weight board call, so the label
  row lands in retail's `s3`. `by += 2` instead rematerialises `by + 2` at
  each use.
- **Size digits are computed before drawing**: `size_high`/`size_low` read
  `breed->size` once, issuing the `div` early and keeping the remainder in
  `s4`.
- **Weight-unit and label rectangles index `get_paraxtbl_2494[lang][8]` and
  `[7]` directly**, so `lang * 60` stays in a register and each field address
  is rebuilt (`lui`/`addiu` + offset). The known-weight flag is read as
  `data->data.fish.flags`, a reload from the spilled `data` parameter.
- **Centre spans first.** `center_w`/`center_h` are computed from the six
  edge bytes before the `w[5]`/`h[5]` initializers, with `fx = x; fy = y;`
  ahead of them. This reproduces retail's six early `lbu`s and the template
  copy order (the first unresolved window in `midday-20261008.md`).
- **`item_no > 1`** gives retail's `slti at` branch form (`>= 2` computes
  into `v0`).
- **Loop initializers** are `cy = 0, row = 0` and `cx = 0, col = 0`.
- **`poffset_2511` is a complete `s8[7]` array**, with one byte per runtime
  language. Its declared retail size is seven bytes; the eight-byte `.sdata`
  reservation includes one padding byte. The earlier incomplete `[]`
  declaration prevented gp-relative addressing. The native seven-byte
  definition keeps that addressing and matches the complete object; see
  [data-migration-20261008.md](data-migration-20261008.md).
- **The label row `24.0f + fy` is written at each use** instead of a
  `label_y` local. The repeated float expression is CSE'd into `f20`, and the
  name-label address is scheduled ahead of the constant as in retail.

### Result/counter swap (19 words)

An in-container capture of the GPR interference graph, replayed by the
private colouring simulator, reproduces the draft's colours exactly. The
fish-loop counter, `menu` and `result` are the last three nodes pushed while
simplification is blocked, so their relative virtual-register numbers decide
which of `s0`/`s1`/`s2` each receives. Renumbering searches give one exact
family: **counter > menu > result > the fish-pointer induction temp**, with
every other node unchanged. The draft had the reverse order (block-scoped
counter numbered below `menu`, `result` declared before it).

Named locals are numbered downward in declaration order (first declared is
highest); block-scoped declarations follow the function-scope ones in source
order. Loop-optimisation temporaries are numbered below the last named local;
extra webs of a reused variable are numbered upward from just above `this`.
The fish loop therefore needs its own function-scope counter declared before
`menu`, and `result` must be declared after `menu`:

```cpp
int       i;
int       j;
CAquaMes *menu;
int       result;
...
for (j = 0; j < 6; j++) {
```

`j` is a real counter used only by the fish simulation loop; `i` keeps the
saved-transform loops and cursor columns.

### Menu-id preparation (5 words)

Retail and the 5-word draft hold the same instructions; retail keeps
`aqua_no * 2` in `v0` and schedules the table `lui` after `addu v1,v0,s5`.
The pre-RA scheduler trace shows why: it runs in register-pressure mode
(dual issue, ties in list order). With `ids[i = menu->menu_cursor]` the list
order is `sll, addu, sll, lui, addu, lw(cursor), ...`, so the second cycle-0
pick is the `lui` and `aqua_no * 2` stays live across it, forcing `v1`. When
the cursor load precedes the `lui` in list order, the second cycle-0 pick is
the shift, the `addu` (pressure −1) wins cycle 1, and `aqua_no * 2` dies
before the table address is defined.

An ordinary statement does this. The cursor column is stored in `i` before
the switch:

```cpp
const s8 *ids = &menu_id_tbl_3721[aqua_no * 6];
i = menu->menu_cursor;
switch (ids[i]) {
```
