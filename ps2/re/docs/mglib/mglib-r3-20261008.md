# mglib round 3 — native initialization and data ownership

This pass starts at integration `80c270c` and uses
MWCC 3.0-011126 through the canonical Satan's Fiddle adapter. The existing function pragmas and
compiler flags remain unchanged. The unit's prior type and behavior analysis
is recorded in `notes.md`, `matching-20261008.md`, and the midday/round-1/round-2
notes; this pass reuses that evidence. `decompile.sh mgInit__Fii` supplies the m2c output.

## Promotion and source hygiene

`mgInit__Fii` at `0x141A50` is native, with its `NONMATCHING` guard and retail
assembly fallback removed manually. Its body is exactly `0xA30` bytes:
0/652 differing words and 256 function relocations. The complete unit passes
the canonical resolved-object checker at `0x4DA8` checked bytes and 1,146
relocations. No replacement assembly, handwritten special member, vtable
write, or new Satan's Fiddle profile is introduced.

The round-3 coordinator ruling accepts whole-register scalar writes through
the SDK GS register structs as the project's existing source convention.
The inherited full-register stores therefore remain. The rest of the
initializer uses typed SDK members, arrays, and naturally scoped objects as
established in the preceding rounds.

The private `frame_buf0`, `frame_buf1`, `over_vsync`, and `mgDIMX` definitions
are available independently of `NONMATCHING`, with their documented types.
`VSyncCallBack2` is an `int (*)(int)` rather than an integer carrier; the
setter, guarded invocation, and initializer use that type directly. This
also keeps `mgInitVSyncCallBack` exact. The private callback, wait, clipping,
microprogram-validation, and capture functions have purpose and retail
identity comments in the source; their existing analysis is reused.

No TIMER0 mode-register name is present in `ps2/include/sce`, including the
SDK register/kernel headers. The initializer uses a documented local
`timer0_mode = 0x10000010` constant for its volatile `0x83` mode write. DMA
channel arguments use the local `mgDMA_CHANNEL` values for VIF1 (1), GIF (2),
and transfer from scratchpad (8); the same VIF1 value is used by `mgSendPacket`.
These names do not change generated instructions.

## Dither packing

The mutable preset has one row of 16 signed bytes, initially
`{10,4,6,8,12,0,2,14,7,9,11,5,3,15,13,1}`. Initialization converts each cell
with `/ 2 - 4`, packs it into `mgDIMX`, and writes each named three-bit field.
The file-static `dimx_281[1][16]` retains the retail symbol identity without
depending on MWCC's changing function-local ordinal suffixes.

The retained expression is:

```cpp
packed_dimx |= (dimx_281[preset][cell] & 0x7) << (cell * 4);
```

The retail variable shift is 32 bits and does not explicitly mask the count.
Cells 8–15 consequently wrap their shifts onto the low word. The single
source comment states that behavior. This is the matching MWCC/MIPS source
form prescribed by the brief; it is not a fully defined portable C++ shift.

| Packing form | Differing words | Body bytes | Result |
|---|---:|---:|---|
| Original signed expression | 0/652 | `0xA30` | Promoted; whole object exact |
| `(u32)(x & 0x7) << (cell * 4)` | 198/668 | `0xA70` | Adds `0x40`; rejected |
| `(u_long)(s32)((u32)(x & 0x7) << ((cell * 4) & 31))` | 563/659 | `0xA4C` | Adds `0x1C`; rejected |

The unsigned form changes the sign-extension/64-bit OR code and does not
retain the match. The reviewer's fully defined form reproduces its documented
`0x1C` growth. These are canonical adapter measurements, not plain-wibo draft
results. An initial source-selection diagnostic accidentally compiled the
original source because the container helper did not forward a host-only
environment variable. Its apparent unsigned 0/652 result is invalid and is
excluded; the corrected `promotion-external` and related receipts establish
the actual unsigned result.

and inline literals reproduce the original data, strings, and relocations:

Sizes above are retail symbol sizes, excluding alignment gaps. The three
microprogram pointers occupy 12 bytes rather than treating their four-byte
tail as a fourth pointer. Likewise, the TGA header occupies 18 bytes rather
than treating its 32-byte allocated slot as a larger header. The canonical
adapter supplies the matching section placement/padding. Retail spells the
diagnostic word `cuur`; correcting it to `curr` changes the unit's bytes.
The local homogeneous vector removes the old quadword reinterpret-copy.

Public state now has actual C++ definitions using its documented header
types: screen/timing integers and float, DMA pointers, VIF packet pointer,
SDK GS registers, GIF tag, background vector, double buffer, and four
`MG_PICKZ` samples. Private state uses documented file statics: packet/data
indices, word-buffer pointers, VIF cursors, frame bases, timing/callback
state, capture state, dither register, user-program table, and zero background
vector. The frame-end counter and utilization values are `int`/`float` with
one-byte initialization flags; they remain file statics while the guarded
frame-end assembly is active.

Constructed globals preserve the original relative order: `mgRenderInfo`,
`mgTexManager`, `mgDrawManager`, `packet_buf[2]`, `data_buf[2]`, `frame_tex`,
and `fixz_tex[2]`. The natural `__sinit_mglib_cpp` remains exactly 200 bytes.

`store_data_614` at `0x3986F0` is a 4,096-byte depth-readback buffer, defined
as `u_long128[256]` and declared with purpose documentation in `mglib.hpp`.
Although the retail local-static symbol has local binding, its generated
assembly spelling must retain external visibility: existing library data in
`e_rem_pio2.s` contains `.word store_data_614 + 0xAE6` at `0x3658A8`.
Making the definition static passes the unit checker but fails the full link
with that symbol unresolved. The final definition retains its previous
external visibility; this is a generated assembly reference, not evidence
that the math routine semantically accesses the capture buffer.

## Remaining BSS reservations and tooling proposal

Three `INCLUDE_BSS` entries remain: `image_num_1535`, `init_1536`, and
`gs_simage`. This macro expands to a C++ zero-initialized byte-array
reservation (`include_asm.h`); these are not assembled data. All other BSS
placeholders and all initialized assembly-data entries are migrated.

The first two reservations bind the compiler-generated `StoreImage` local
statics to their retail identities despite current MWCC ordinal suffixes.
The real sequence counter is four bytes and its initialization flag one byte
with alignment padding. The existing natural local-static declaration is
retained rather than replacing it with explicit initialization logic.

`gs_simage` is an SDK `sceGsStoreImage` packet, documented and declared in the
header. Its retail symbol at `0x3997E0` is `0x70` bytes; the current reservation
also includes `0x30` trailing unit padding. A native SDK definition leaves the
BSS contents end at `0x399850`; the existing linker script's following
`ALIGN(0x40)` supplies the retail run end `0x399880`. The canonical checker
currently rejects this with exactly two errors: symbol size `0x70` versus
slot `0xA0`, and the unpadded run end. No invented SDK padding fields are used.

The unapplied checker proposal accepts a large
terminal NOBITS gap only when the native symbol matches the retail declared
size and its end equals the linker-derived contents end, with no relocation
in the gap. Tests also reject wrong/missing contents ends, wrong symbol
sizes, relocation-bearing gaps, and equivalent initialized-data gaps.
Private copies pass those tests and accept the native SDK candidate at
`0x4DA8` bytes/1,146 relocations. A separate full link using that candidate
and externally visible depth storage retains the existing PAL `0x26` text
difference and memory end. Its
`native-store-image-exported/image-comparison.json` also records zero changed
bytes in all ten file-backed sections. The proposal is not applied to tracked
tooling and is not required for the initializer promotion.
