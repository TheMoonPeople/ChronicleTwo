## Frame-texture metadata

`image_blocks` copy: the zero store is at `0x144874`, the load at
`0x14487C`, and the copy store at `0x144890`. This supplies a new statement
order hypothesis without changing the documented texture layout.

| Private trial | Differing words | Body |

The packet reservation remains unresolved. Retail computes an endpoint,
subtracts the start address, and applies signed byte-count division by
four. The SDK exposes typed `pCurrent`, `Terminate`, `Reserve`, and the
out-of-line packet writers; it has no count getter or inline packet
builder. A fixed typed packet extent folds to 32 words, while integer
address casts or byte-pointer subtraction violate this lane's rules.
No such expression or invented API is introduced.

## Frame-end packing and depth storage

Grouping the three DISPLAY expressions as
`DH | (display_position | DW)` reproduces the retail OR operand tree in
source but still gives **232/672** with the same `0xA34` body. No change is
retained. The previously recorded packed-field and union/word-view probes
are not repeated.

`u_long128` is `unsigned __int128`, and `sceGsExecStoreImage` accepts a
`u_long128 *`. A new integral extraction probe keeps that actual storage:
`(u_int)(store_data[pixel / 4] >> ((pixel % 4) * 32)) & 0xFFFFFF`.
MWCC rejects both the plain and regrouped-display versions with
`illegal data size`; it supplies no lawful matching replacement for the
inherited scalar-pointer reads. No source type-pun is added or promoted.

Activation also requires reconciling the guarded local statics with the
already native `count_580`, `cpu_ratio_583`, `free_ratio_586`, initialization
flags, and exported `store_data_614`. The isolated complete-object baseline
reports extra BSS/SBSS pieces from those duplicate locals, in addition to
the function mismatch. The documented library-data reference still requires
the exported readback symbol. A function-only score cannot authorize its
removal or a promotion.

## Round 2 — mgEndFrame guarded draft 232 → 55

Base `750320ef`, image `chronicletwo_dev:sf-63f7a9e`, production profile.
The guarded draft improves from **232/672 to 55/672** and its body grows from
`0xA34` to retail's declared size `0xA74` (2676). Two source facts:

- **Display-environment writes are whole-register writes.** Retail reloads
  `mgDBuffID` and recomputes `&mgDBuff.disp[mgDBuffID]` after each of the
  BGCOLOR, SMODE2 and DISPFB stores; plain member stores let MWCC keep the
  index and address in registers. Writing those three as
  `*(u_long *) &mgDBuff.disp[mgDBuffID].bgcolor = 0;` (the accepted GS
  whole-register convention, as the DISPLAY store already was) restores
  the reloads (232 → 217 for BGCOLOR/SMODE2 alone). PMODE keeps plain stores:
  its reload already follows the antialiasing branch join.
  In the real SDK these members are `tGS_*` bitfield registers, which is why
  the original code needed the cast; this repository's simplified
  `sceGsDispEnv` declares them `u_long`.
- **DISPFB values are recomputed from the FRAME fields at each use, each
  field widened before shifting**:
  `(u_long) frame->FBP | ((u_long) frame->FBW << 9) | ((u_long) frame->PSM << 15)`
  (the `SCE_GS_SET_DISPFB` expansion). Retail reloads the fields for the
  environment store, `GS DISPFB1` and `GS DISPFB2`, with 64-bit `dsll` and
  no final sign extension; the former `display_base` local computed in
  32 bits, sign-extended, and was reused for DISPFB2. The DISPLAY prefix
  `display_position` stays a local: retail keeps it in `s3` across
  `FlushCache`, `sceGsSwapDBuff` and `sceDmaSync` while reloading the screen
  size for each width/height term.

Declaring `display_position` before `magnification` gives 55; the reverse
gives 58. The position of `frame` among the entry declarations, declaring
`frame`, `magnification` or `display_position` at their assignments, if/else
instead of the ternary frame selection, and `mgDBuffID ?` without `!= 0`
leave 55 or 58. Moving `display_position` after the DISPFB store recomputes
the screen-height term (0xA78, 210); computing it before the frame selection
or splitting the magnification term into a later `|=` gives 58–80.

Remaining 55 words: the documented depth-mask temporaries at
`+0x550..+0x560` (3); `frame` and `display_position` exchange `s1`/`s3`
(retail frame `s1`, magnification `s2`, display position `s3`) with the
resulting schedule of the `+0x744..+0x7C8` window; and the frame-counter
tail at `+0xA0C..+0xA20`, where retail stores the incremented count before
the division-by-zero branch. Activation still needs the local-static
reconciliation recorded above: retail's lazily initialized
`count$580`/`cpu_ratio$583`/`free_ratio$586` with `init$581/584/587` flags
are file-scope `count_580`… definitions while the function is assembly; the
private full-wrapper probe (`.private/nmmenu-r2/mglib/ef-r2-retained-full/`)
reports the resulting extra `.sbss`/`.bss` pieces and unresolved symbols.
Trials: `.private/nmmenu-r2/var/{ef,eg,eh,ei,ej,ek}-*` and their
`.private/nmmenu-r2/mglib/` directories.

## Round 2 — mgEndFrame matched (55 → 0) and activated

The guarded draft reaches **0/672** and is promoted. Source facts, each
measured from the 55-word draft (trials `.private/nmmenu-r2/var/el-*`):

- **The DISPLAY prefix is a compiler CSE, not a local.** Writing the full
  `(u_long) 0x290 | ((u_long) (offset_y + 72) << 12) | ((u_long) magnification << 23) | …`
  expression at the environment store and at both GS DISPLAY writes lets
  MWCC keep the common left-associated prefix in `s3` across `FlushCache`,
  `sceGsSwapDBuff` and `sceDmaSync` while it reloads the screen size for the
  width/height terms. As a low-numbered CSE temporary it is coloured after
  the named locals; the former named `display_position` local was coloured
  first and took `s1` (55 → 33). Declaration order of `offset_y` and
  `magnification` or of `frame` among them leaves 33.
- **Magnification is a conditional expression**:
  `magnification = mgScreenWidth == 512 ? 4 : 3;` gives retail's `frame` in
  `s1` and `magnification` in `s2` (33 → 15). `if`/`else` gives 33; `if`/`else`
  or a default-then-`if` frame selection gives 46 and 249.
- **The vertical offset keeps `+ 72` in the register expression**:
  `offset_y = (524 - mgScreenHeight) / 2;` with `(offset_y + 72) << 12`
  reproduces retail's difference/quotient temporaries (`v0`/`v1`); `+ 72` in
  the local (either operand order) leaves 15 and `72 - (mgScreenHeight - 524) / 2`
  gives 41.
- **Frame counter compare reads the counter first**:
  `count++; if (count > 60 / mgFrameRate)` stores the count before the
  division check and reloads it in the branch delay slot. `60 / mgFrameRate < count`
  with `count++`, `++count` or `count += 1` leaves the 6-word tail.
- **Depth sample**: `u_int depth = pixels[0]; depth &= 0xFFFFFF;` makes the
  first AND share the load's register (retail `a0`) with the mask in `v0`.
  `int depth = pixels[0] & 0xFFFFFF` (either operand order, or `% 0x1000000`)
  leaves the 3 mask words; `(int) pixels[0] & 0xFFFFFF`, `int` source with
  `&=`, or `(… << 8) >> 8` select the two-shift form (0xA6C); a `u_int`
  initialized with the mask gives 4; `int depth; depth = (u_int) depth & 0xFFFFFF` 12;
  the `u_int` form with an uncast compare 1. Moving `depth` or `pixel` to
  function scope leaves 3 or 9.
- **Typed storage without a pun**: the read-back buffer is
  `static u_int store_data[1024]`, passed to `sceGsExecStoreImage` as
  `(u_long128 *) store_data`. Indexing the array directly folds `[0]` into a
  direct symbol load (8 words); a plain or pointee-`const` pointer copy is
  propagated back (9). `u_int *const pixels = store_data;` keeps retail's base
  register for the first sample and the loop (0), the documented top-level
  `const` limit on copy propagation.

Activation: the native function-local statics (`count`, `cpu_ratio`,
`free_ratio` with MWCC's initialization guards, and `store_data`) replace the
former file-scope `count_580` … `init_587` definitions and the global
`store_data_614` array. Those become `INCLUDE_BSS` reservations at their
retail `.sbss`/`.bss` positions (each guard reservation spans its byte and
the following alignment padding, as `init_1536` does for `StoreImage`);
the postprocessor binds the statics by base name and extent and the guards
by retail gp-relative address. `store_data_614` stays global for the
library-data reference in `e_rem_pio2`. The stale
`extern u_long128 store_data_614[256]` header declaration had no users and
is removed. TIMER0 and the GS PMODE/DISPFB/DISPLAY registers use named
address constants beside the existing `timer0_count`.

Validation (`.private/nmmenu-r2/receipts/ef/`): build `SCES_511.90: OK`
(6775 perfect, 97 asm); `check_objects` 149/149 with mglib at `0x4D9C`
bytes and 1,228 relocations (the native function ends at `0xA74` inside its
`0xA80` piece; native gp-relative references add relocations); compared with
the menusys-promotion hashes only `mglib.cpp.o` and `SCES_511.90` differ.

## Round 2 — mgSetPkFrameBuffer guarded draft (packet count isolated)

Measured with the packet count written as a typed pointer difference so the
later code stays aligned (trials `.private/nmmenu-r2/var/fb-*`):

- **The packet count is MWCC's pointer difference.** A toy compile shows
  `(u_int *) (q + 12) - p`, with `q = (u_long *) (p + 8)`, emits retail's
  `addiu +0x20`, `addiu +0x60`, `subu`, `sra 2` with the `bgez`/`addiu 3`
  rounding correction; a typed pointer difference uses signed division.
  `sceVif1PkReserve(vif, (u_int *) &registers[12] - packet)` gives 240 from 252
  and aligns the packet window and the body size.
- **FRAME is read as a whole register**: `*(u_long *) &frame`, like XYOFFSET
  and SCISSOR, materializes the stack address before the `ld` (240 → 161).
  The real SDK `sceGsFrame` has no `value` member, so the original source had
  to read it this way.
- **Each `bpp` case has its own body**: PSMCT16 and PSMCT16S are separate
  `case` blocks that both set 16 (161 → 96), and `bpp` is an `int`
  (with merged cases `int` gives 146; together they align the metadata).
- **Both shift counters are cleared before the first log2 loop**
  (`width_shift = 0; height_shift = 0;`): 48.
- **The log2 loops test `size > 1`**: the entry test then fuses into the
  branch with the `size = width` copy in its delay slot (48 → **0**).
  `for (int scan = …)`, a separate `scan` local (56 each) and a `while` form (48)
  do not.

With all five changes the function is **0/424** and the whole private
mglib object passes `check_objects` (no errors, `0x4D9C` bytes, 1,248
relocations; `.private/nmmenu-r2/mglib/fb-l3-full/`). The function is
promoted with the retail count written as the typed pointer difference
`sceVif1PkReserve(vif, (u_int *) &registers[12] - packet)` over the existing
`(u_long *) &packet[8]` register view, the same pointer-difference reserve
count matched upstream code uses (`tag - start` in `mg_drawprim.cpp`,
`cursor - start` in `mg_texture.cpp`). With the constant `32` the packet
window is six words short and everything after it misaligns (251/424).
