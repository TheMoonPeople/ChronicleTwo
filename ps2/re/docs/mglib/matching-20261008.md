The current source state includes the round-3 promotion from `80c270c`, with
MWCC 3.0-011126, canonical `-O3,p` flags and Satan’s Fiddle from image

## Native shadow compositor

`mgEndDrawShadow__FP10mgCTextureP10mgCTexture` is native. Its ALPHA members are
initialized in register field order (`a`, `b`, `c`, `d`, `fix`). This produces
the retail scheduling of the independent FIX byte store and low-byte masks.
The draft changes from 25/204 differing words (0x328 code) to zero; retail’s
extent is 0x330. The complete unit has zero byte or resolved-relocation
differences: 0x4DB8 checked bytes and 1,049 relocations.

The SDK `sceGsDBuff` declaration already present in `mglib.hpp` supplies the
correct layout. `mgBeginFrame` can address the named clear-colour bytes and
draw-frame fields directly while remaining exact. No shared header needs a
change, and the source-only byte-array redeclaration is unnecessary.

## Native framebuffer copies

Upstream's `MGLIB_IMPLICIT_TEX0_ASSIGNMENT` declaration switch now allows
implicit `mgCTexture` member copies in this unit while retaining the custom
TEX0 operator in `mg_texture`. `mgGetFrameBuffer` and `mgGetFrameBackBuffer`
are native at `0xF8` and `0x138` bytes; their earlier shared-header park is
resolved. The SDK declaration difference and its ODR concern are documented
in [notes.md](notes.md). The local shadow compositor remains native.

Direct access to the existing global draw-buffer and frame-texture objects
avoids hoisting redundant pointers for the three large functions. The frame-end
routine samples frame ticks before lazy static initialization, scopes the
readback image after the drawing primitive, and validates sample x and y
bounds separately. It uses negated `<=` comparisons where retail `c.le.s`
branches also handle unordered floating values. The display slot is the
actual `disp[mgDBuffID]` array element. These are guarded behavioral/source
improvements; they do not qualify as native matches.

The midday pass restores `GetScreenSize`'s documented retail-local binding,
copy-constructs the frame register at its actual use, and scopes the dither
preset loops. Detailed type evidence, intermediate scores and validation are
in [mapmglib-midday-20261008.md](mapmglib-midday-20261008.md).

### Blockers and reconsideration triggers

- **Interrupt control:** `VSyncCallBack` needs the inline retail `sync; ei`
  epilogue. Reconsider only with a verified compiler/SDK intrinsic that emits
  those instructions from acceptable source; an external `EIntr` call does
  not provide the same object.
- **Framebuffer source/allocation:** the default-frame `t3` allocation and
  early frame copy now agree with retail through +0x26C. Remaining differences
  begin at +0x270 with packet emission/reservation, followed by texture metadata
  and dimension-loop allocation. The retail dynamic reservation-size expression
  is not reproduced by the fixed 32-word reservation. Reconsider with natural,
  compliant packet-construction evidence rather than raw cursor arithmetic.
- **Initialization promotion, resolved:** narrowed chained ZBP assignment,
  chained global ZBUF copies, and sequential direct context construction restore
  the context windows and both dither loops. Round 2 interleaves the FRAME writes
  with background initialization and places the clear flag last, resolving
  +0x320..+0x36C and reaching 0/652. Round 3 accepts the existing whole-register
  casts under the coordinator ruling and removes the guard after migrating
  initialized data and restoring typed globals. Unsigned dither packing adds
  `0x40` bytes; the fully defined masked form adds `0x1C`, so the original
  signed expression remains with its 32-bit wrap comment. Earlier typed-copy
  and intrinsic failures remain documented in [mglib-r2-20261008.md](mglib-r2-20261008.md).
- **Frame-end source/allocation:** the first remaining words are at +0x550:
  the depth mask and initial sample load use different temporaries and the
  commutative AND operand order differs. Other code is exact through +0x6CC;
  display indexing/addressing and packed register expressions differ from
  +0x6D0 onward. Reconsider with natural depth-buffer element typing and the
  SDK’s display-packing source expressions before any scheduling calibration.

GPR helper-history masks 0, 0x10 and 0x30 produce identical initial drafts in
this unit. The improved frame-end performance-meter floating calls already
match retail before the integer depth/display differences, so no verified
helper-history or floating-order profile row follows from this evidence.
`mgInit` needs no profile row.
