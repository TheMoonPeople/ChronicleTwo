## Register initialization hygiene

The five inherited stores write the complete 16-byte `mgGiftagAD` and
eight-byte `mgTEX1_1`, `mgTEST_1`, `mgALPHA_1`, and `mgTEXA_1` through
scalar pointers. The complete source values are zero, 0x261, 0x5000B,
0x44, and 0x100400000 respectively. Their existing field layouts and the
two draw contexts are documented in the earlier unit notes.

The available TEST and ALPHA declarations expose real `value` members.
TEX1, TEXA, and GIF lack equivalent packed members in the shared SDK
header. This is a separate source-compliance problem from the resolved
background scheduling; it is not addressed by removing the function guard.

New replacements were measured privately. Representative results are:

Direct typed value stores allow MWCC to reuse the assigned scalar for the
second context. Retail instead loads the first register again and uses
address-based stores. Aggregate construction introduces literal loads and
stack temporaries. Ordinary `memcpy` remains an out-of-line call, including
the `inline_intrinsics` and level-4 probes. Native global definitions,
explicit object alignment, typed pointers, pointer arrays, and explicit
copy construction do not recover the missing operations. None of those
alternatives is retained. The full private ledger records every result
and the source used for it.

The compiler recognizes `__memcpy(void *, void *, unsigned int)` without
a new declaration. A const source or fourth alignment argument fails its
type check. Accepted mutable-source calls crash the pinned compiler with
SIGSEGV at address 0xC. Immediate and local sizes, typed and scalar sources,
explicit void-pointer conversions, a used return value, intrinsic inlining,
and disabling the global optimizer do not avoid the crash. Plain wibo also
exits 139 for the mutable GIF-copy input, so that failure is reproduced
outside the Satan's Fiddle wrapper. No compiler, wrapper, or SDK change is
made to work around it.

The previously proposed packed SDK views are tested only through an ignored
private header copy. There is no new shared-header proposal or accepted
profile row. Their member-pointer variants still fail to match, and the
prior GIF type-alignment concern remains unresolved. These results do not
authorize a header change or a promotion.
