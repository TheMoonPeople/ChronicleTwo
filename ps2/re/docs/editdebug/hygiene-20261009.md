# editdebug hygiene pass (2026-10-09)

`LightingEdit`: new `LIGHTING_EDIT_ROW`, `LIGHTING_EDIT_DIR_ITEM` and
`LIGHTING_EDIT_FOG_ITEM` (editdebug.hpp), following the header's
`EDIT_DEBUG_*_ITEM` pattern. Checked with a PAL build (`SCES_511.90: OK`) and `check_objects.py` (149/149).

Evidence:
- Row 0 prints `"%sLightSet [%d]"` with `cursor[row == 0]`; left/right on it
  change `light_no` and move the scene time to that set. Row 1 is the page
  selector (and the light on the directional page); a page change lands on
  row 1. Each page's own entries start at row 2 (`edit = row - 2` on all four
  pages). `LightListNum = {11, 8, 9, 3}` is 2 + {9, 6, 7, 1}.
- Directional page: rows 0-2 select the colour component (`COL R/G/B`),
  3-5 rotate about axis `edit - 3` (`ROTATE X/Y/Z`); 6 entries.
- Fog page: switch cases 0..6 edit `near_dist`, `far_dist`, `color[0..2]`,
  `far_value` and `near_value`, labelled NEAR/FAR/R/G/B/MIN/MAX; 7 entries.

Left literal: the cursor wraps (`row = 0`, `LightListNum[...] - 1`),
`row > 10`, `DirLightNo` 0/3, the one-entry file page. All casts convert
float/int or downcast. No `unk_` accesses; header block agrees with
`main.symbols.txt`. Outside this scope: `LightListNum` could be written with
the new enums.
