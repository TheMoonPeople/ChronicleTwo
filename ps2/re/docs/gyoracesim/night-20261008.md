## Source evidence

Both functions reuse C-style loop variables across disjoint loops. MWCC splits
such a variable into one live-range web per loop and numbers those webs below
the optimizer's induction and invariant temporaries. That numbering decides
the final loops' register order (see the allocator model below).

CollisionFish:

- `j` is declared after `old_index`, used by the sort's inner loop and reused
  as the inner index of the lane separation loop.
- The lane loop reuses `i` as its counter (`for (i = 0; i < 6; ++i)`).
- `current` is declared at function level, takes `&fish[index]` in the
  bucketing loop to read the lane, and is reused as the following fish in the
  separation loop. `ahead` stays scoped to the lane loop.

StepGyoRace:

- `int i, j;` at function level. `j` counts the opening rank/goal-time clear
  loop and both inner rank loops. The final rank loop then compares
  `i != j` directly, with no `number` local, unsigned counter or casts.

## MWCC allocator model

Recovered from `mwccps2.exe` 3.0-011126 (SHA-256 `0e16a5d6…`) under LLDB and
confirmed by simulation; useful for any register-permutation near miss.

- Simplify (`0x4AEDC0`): `K` is the class's register budget returned by
  `0x498E40` (25 for GPRs here). Nodes are scanned in increasing virtual
  register number from the first virtual index. A node whose current degree
  is below `K` is pushed and its neighbours' degrees drop immediately (by two
  for paired registers, flag `0x200`). Passes repeat until nothing is pushed;
  leftovers go to spill selection.
- Colouring (`0x4AF0F0`, called from `0x4AF49D`) pops the stack, so later
  pushes are coloured first, and assigns the first free register in the order
  `v0 v1 a0–a3 t0–t7 t8 t9 s0–s7`.
- Node array: global `0x57C778`, stride `0x1E` (+0x10 index, +0x12 colour,
  +0x14 flags, +0x16 degree, +0x1A edge list). Basic blocks start at
  `0x57C750`.
- Simulating simplify with `K = 25` and that colour order reproduces every
  captured colouring exactly (eight CollisionFish variants); `K = 26` fails
  two of them.

Observed virtual-register numbering in these functions, highest first:
single-web user locals (reverse declaration order), then strength-reduced
induction temporaries, then hoisted invariants such as the lane row base,
then extra webs of reused variables. Extra webs are numbered per variable in
program order. The variable order did not follow declaration order: `j`'s
webs precede `i`'s until `j` is used before `i` in StepGyoRace.

Applied to the CollisionFish lane loop, retail's assignment (inner offset
`a3`, row offset `t0`, count offset `t1`, row base `t2`, lane counter `t3`,
inner index `t4`, ahead pointer `a2`) requires the counter, inner index and
ahead pointer all below the row-base invariant, with the counter above the
other two. Only reused variables are numbered that low. A fresh `lane_no`
(any declaration point) is numbered above every temporary and takes `a3`
first. The previous 72-variant counter/scope matrix and the
pragma sweep below never had all three numbered that way.
